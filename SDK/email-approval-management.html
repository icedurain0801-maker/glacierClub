邮箱审批管理 — 需求说明
1需求概述

背景 / 目标：玩家在更换常用邮箱、原邮箱注销或无法登录等场景下，需要解除或更换通行证绑定的密保邮箱。该操作涉及账号安全，不可由玩家自助完成，须由运营人员人工审核。本页面将原「邮箱解绑审批」升级为统一的邮箱审批管理界面，同时受理「解绑」与「换绑」两类申请，集中完成查询、审核、留痕，降低账号被盗、误操作风险。

用户对象：玩家中心运营 / 客服审核人员（具备「邮箱审批管理」菜单权限的后台账号）。

3详细字段定义
3.1 列表字段
字段名称枚举值 / 说明
绑定ID绑定关系唯一标识，列表唯一键
冰川通行证名称账号名
冰川通行证ID账号唯一 ID
游戏名称申请来源游戏，格式「游戏名(游戏ID)」
操作类型解绑 / 换绑，以 Tag 区分
原邮箱当前绑定邮箱，脱敏展示
新邮箱换绑目标邮箱，脱敏展示；解绑时为空，显示「—」
审核状态待审核 / 审核通过 / 已拒绝
绑定时间原邮箱绑定时间
申请时间玩家发起申请时间
申请原因玩家填写的申请理由
审核人仅已审核；处理该条的运营账号
审核时间仅已审核；审核动作发生时间
审核备注仅已审核；审核人填写的说明
3.2 审核弹窗表单字段
字段类型必填默认值校验 / 枚举
通行证名称 / ID只读—带入行数据不可编辑
操作类型只读—带入行数据解绑 / 换绑
原邮箱只读—带入行数据脱敏
新邮箱只读—带入行数据仅换绑显示；解绑隐藏该行
审核结果下拉是审核通过审核通过 / 拒绝
审核备注文本域是空≤200 字；通过与拒绝均必填
审核备注为必填项，无论通过或拒绝均须填写，便于事后追溯与玩家申诉。
4功能逻辑与筛选项
搜索 / 筛选
  • 双 Tab 独立筛选：「待审核记录」与「已审核记录」各自维护独立筛选条件，切换 Tab 不串用，互不影响已勾选状态。
  • 平台（必选）：默认「国内冰川平台」，为强制约束项，决定下方游戏、记录的数据域。
  • 操作类型：默认 不限，可选「解绑 / 换绑」，单独筛选某一类申请。
  • 游戏：可搜索下拉，游戏ID 精确匹配 + 游戏名称模糊匹配；不输入时默认「不限」。
  • 通行证：下拉切换「名称 / ID」+ 输入框联动查询。
  • 原邮箱：按原绑定邮箱模糊查询。
  • 时间范围：待审核按「申请时间」、已审核按「操作时间」过滤。
  • 审核状态：仅已审核 Tab 提供，默认「不限」，可选「审核通过 / 已拒绝」。
核心操作
  • 单条审核：点击行内「通过 / 拒绝」→ 弹出确认弹窗并带入该行只读信息。换绑额外展示新邮箱行，解绑自动隐藏。确认后二次提交。
  • 批量审核：勾选多条后「批量审核」按钮高亮（默认置灰不可点），弹窗统一选择结果与备注，对所选记录批量提交。
  • 结果反馈：提交成功以 Toast 提示，文案含操作类型与通行证信息（如「换绑申请审核通过：xxx（id）」）。
  • 关闭交互：弹窗 / 抽屉支持点遮罩、× 按钮、Esc 三种方式关闭。
5异常与边界情况
数据异常
  • 列表无数据时展示空状态（空数据插画 + 文案），分页显示「共 0 条」。
  • 解绑记录「新邮箱」恒为空，统一以「—」占位，不可留白造成歧义。
性能 / 容量
  • 列表默认分页 10 条/页，服务端分页，避免一次性加载大数据量。
  • 批量审核需限制单次最大条数（建议 ≤ 100），超出时提示分批处理。
  • 时间范围筛选限制最大跨度为 1 年，超出时 Toast 提示「查询时间范围不能超过 1 年，请重新选择」，防止全表扫描。
权限边界
  • 无「审核」权限的角色：仅可查询，行内「通过/拒绝」与「批量审核」按钮置灰不可点（非隐藏），以便用户知晓功能存在。
  • 邮箱等敏感信息统一脱敏展示，不返回明文。
操作异常
  • 并发审核：若记录已被他人审核，提交时校验状态，已非「待审核」则提示「该记录已被处理」并刷新列表。
  • 重复点击：提交按钮点击后置 loading 防抖，防止重复提交产生多条审核记录。
  • 提交失败 / 网络断开：保留弹窗与已填内容，Toast 报错并允许重试，不静默丢失。
  • 批量部分失败：返回逐条结果，提示「成功 X 条，失败 Y 条」，失败项保留可重试。
⚠️ 审核为不可逆的安全操作：通过即执行解绑/换绑。务必在确认弹窗中向审核人清晰呈现原邮箱与新邮箱，避免误操作。
