# 专属客服方案页面复刻设计

## 状态

已确认，待实施。

## 目标

在 SDK 管理后台原型中补齐专属客服方案工作流：用户从 `specialScheme.html` 的专属客服方案入口进入方案列表，再通过“新建专属客服”进入新增表单。视觉结构以 `schemeList.html` 为基准，并复刻用户提供的两张参考图。

## 页面与导航

| 页面 | 文件 | 入口与去向 |
| --- | --- | --- |
| 特殊方案 | `admin/schemeManagement/specialScheme.html` | 新增“专属客服方案”入口，跳转列表页 |
| 专属客服方案列表 | `admin/schemeManagement/exclusiveCustomerService.html` | 支持返回特殊方案、打开新建页和查看/编辑演示 |
| 新增专属客服方案 | `admin/schemeManagement/exclusiveCustomerServiceCreate.html` | 提交后写入当前浏览器的演示数据并返回列表；取消或返回不写入 |

三个页面保持与 `schemeList.html` 一致的顶部平台导航、SDK 侧边栏、全局工具栏、标签栏、浅灰工作区和“需求说明”抽屉。

## 列表页

- 筛选项：方案名称，支持查询与重置。
- 主操作：`+ 新建专属客服`。
- 表格字段：方案 id、方案名称、方案关联渠道、专属客服数量、最后操作时间、最后操作人、操作。
- 操作：查看、编辑和删除确认；删除仅影响浏览器会话内的演示列表。
- 分页展示与参考图一致，固定为演示数据的单页状态。

## 新建页

复刻以下字段和默认状态：

| 字段 | 控件/默认值 |
| --- | --- |
| 专属客服名称 | 必填文本输入 |
| 是否开启专属客服 | 必填单选，默认“是” |
| 入口展示位置 | 必填复选，默认“游戏内”选中 |
| 是否提前展示 | 必填单选，默认“是” |
| 游戏内展示文本 | 必填多行文本，最多 5000 字符 |
| 是否重新分配专属客服 | 必填单选，默认“否” |
| 入口屏蔽已添加客服的玩家 | 必填单选，默认“否” |
| 开启金额设置 | 必填数值输入，单位“人民币：元” |
| 专属客服分配类型 | 必填单选，默认“根据权重随机” |
| 专属客服联系方式 | 动态表格，初始一行，支持添加与移除 |

动态客服行字段为序号、客服钉钉姓名、客服钉钉手机、联系方式名称、联系方式类型、联系方式、权重、使用者和操作。表单支持提交、重置、预览与返回。

## 交互与数据边界

- 所有数据为前端 mock 数据，不接入网络接口、持久化服务或真实客服数据。
- 通过 `sessionStorage` 在当前浏览器会话中维持新建、编辑和删除后的列表状态；新会话恢复初始 mock 数据。
- 提交时校验必填项、展示文本长度、金额非负及至少一位客服；错误显示在相应字段附近。
- 预览以模态框展示当前已填写内容，不写入数据。
- 小屏下允许表格横向滚动，导航和表单不发生遮挡。

## 验收与验证

1. 从特殊方案入口可打开列表页，列表页的新建按钮可打开新增页。
2. 列表筛选、重置、删除确认和标签关闭可用。
3. 新建页的动态客服行增删、表单校验、重置、预览和提交可用。
4. 成功提交后列表中出现新方案；返回或取消不新增。
5. 在桌面和窄屏视口检查页面无内容重叠或横向主体溢出。

## 非目标

- 不接入后端 API、权限、真实用户数据或真实客服分配。
- 不修改 `schemeList.html` 和正在运行的其他本机服务。
