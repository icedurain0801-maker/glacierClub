在「配置中心 → 支付配置管理」新增7个三方支付类型：Terminal3支付（T3）、Razer支付、Xsolla支付、Adyen支付、PayerMax支付、Waffo支付、Checkout支付。各类型分别配置对应渠道参数，原有6种类型保持不变。

支付配置按照游戏ID维度进行配置：每份支付方案归属于对应游戏ID，不同游戏的支付参数应相互隔离。gameId 是配置归属维度，不作为本页需要手工填写的支付参数；具体游戏上下文获取方式待确认。

T3（Terminal3支付）字段

字段名称字段限制字段说明
公钥（publicKey）必填，文本；最大长度99999999字符，格式不限Terminal3 的 Project Key，用于识别渠道项目。
私钥（privateKey）必填，密码输入；最大长度99999999字符，格式不限Terminal3 的 Secret Key，渠道支付鉴权凭据。
沙盒支付（sandBox）必选，是/否；默认否true 为沙盒环境，false 为正式环境。

Xsolla支付字段

字段名称字段限制字段说明
项目ID（projectId）必填，文本；最大长度99999999字符，格式不限Xsolla 平台的项目标识，不等同于游戏ID。
API密钥（apiKey）必填，密码输入；最大长度99999999字符，格式不限用于 Xsolla API 请求鉴权。
通知密钥（notifyKey）必填，密码输入；最大长度99999999字符，格式不限用于 Xsolla Webhook 支付通知校验。
沙盒支付（sandBox）必选，是/否；默认否true 为沙盒环境，false 为正式环境。

交互规则

字段规则：七种新增渠道文本参数必填，最大长度99999999字符，格式不限；私钥及API、签名、通知、授权密钥为密码输入，公钥和标识为文本输入。Razer仅配置 applicationCode 与 secretKey，不配置 gameId 或沙盒支付。方案名称最多100字符。T3、Xsolla沙盒默认否。取消返回支付配置列表。

  1. 选择所属游戏后配置对应支付方案，配置归属以游戏ID为维度。真实游戏切换与配置保存接口不在当前静态原型中实现。
  2. 选择 T3、Razer 或 Xsolla 后展示对应渠道字段；切换方案类型保留各类型独立的页面内草稿，不能混用渠道凭据。
  3. 除回调地址类型外，启用状态默认开启，可切换为停用。
  4. Terminal3、Razer和Xsolla支付不配置 gameId；Razer不配置沙盒支付，T3、Xsolla的 sandBox 默认「否（正式环境）」，可切换为「是（沙盒环境）」。
  5. 提交时检查必填项和字段格式，错误显示在字段下方；取消返回支付配置列表。

详情参数脱敏

配置列表和待审核列表提供只读「详情」。所有支付参数统一脱敏：长度大于8时保留前4位和后4位，中间为***；长度不超过8时仅显示***；空值显示—。方案名称、方案类型、启用状态、游戏版本正常展示。详情不提供明文切换，复制仅能得到脱敏值；DOM、title和辅助属性不放入参数明文。编辑表单不受此展示规则影响。

游戏版本唯一性

游戏版本非必填。同一游戏ID、同一支付类型下，相同游戏版本最多一条，不指定游戏版本也最多一条；新增和编辑均校验，编辑排除自身，不受审核或启用状态影响。重复时toast提示：该支付类型下已存在此游戏版本的方案，请勿重复创建；空版本重复提示：该支付类型下已存在未指定游戏版本的方案，请勿重复创建。无默认方案，不自动回落匹配。新增与编辑仅页面内保存演示，刷新恢复。
