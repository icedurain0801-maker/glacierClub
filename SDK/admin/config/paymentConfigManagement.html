需求说明 · 支付配置管理

本次需求：新增 Xsolla、T3 支付

在「配置中心 → 支付配置管理」的方案类型中新增「Xsolla支付」和「Terminal3支付（T3）」，支持分别配置对应渠道的支付参数，原有支付类型保持不变。

支付配置按照游戏ID维度进行配置：每份支付方案归属于对应游戏ID，不同游戏的支付参数应相互隔离。gameId 是配置归属维度，不作为本页需要手工填写的支付参数；具体游戏上下文获取方式待确认。

基础字段

字段名称字段限制字段说明
游戏ID（gameId）配置归属维度；无需手填标识本配置所属游戏；上下文获取方式待确认。
方案类型必填，下拉单选本次新增 Xsolla支付、Terminal3支付（T3）；支持搜索选择。
方案名称必填，最多100个字符用于识别支付配置方案。
启用状态启用/停用；默认启用标识该支付方案是否启用。

T3（Terminal3支付）字段

字段名称字段限制字段说明
公钥（publicKey）必填，文本；最大长度99999999字符，格式不限Terminal3 的 Project Key，用于识别渠道项目。
私钥（privateKey）必填，密码输入；最大长度99999999字符，格式不限Terminal3 的 Secret Key，渠道支付鉴权凭据。
沙盒支付（sandBox）必选，是/否；默认否true 为沙盒环境，false 为正式环境。

Xsolla支付字段

字段名称字段限制字段说明
项目ID（projectId）必填，文本；最大长度99999999字符，格式不限Xsolla 平台的项目标识，不等同于游戏ID。
API密钥（apiKey）必填，密码输入；最大长度99999999字符，格式不限用于 Xsolla API 请求鉴权。
通知密钥（notifyKey）必填，密码输入；最大长度99999999字符，格式不限用于 Xsolla Webhook 支付通知校验。
沙盒支付（sandBox）必选，是/否；默认否true 为沙盒环境，false 为正式环境。

交互规则

  1. 选择所属游戏后配置对应支付方案，配置归属以游戏ID为维度。真实游戏切换与配置保存接口不在当前静态原型中实现。
  2. 选择 T3 或 Xsolla 后展示对应渠道字段；切换方案类型保留各类型独立的页面内草稿，不能混用渠道凭据。
  3. 同一游戏同一渠道是否允许多个方案、重复配置策略、权限及接口失败处理待确认。
  4. 除回调地址类型外，启用状态默认开启，可切换为停用。
  5. Terminal3支付和Xsolla支付不配置 gameId；sandBox 默认「否（正式环境）」，可切换为「是（沙盒环境）」。
  6. 提交时检查必填项和字段格式，错误显示在字段下方；取消返回配置中心。

配置列表与待审核

支付配置管理默认进入配置列表，提供「配置列表 / 待审核」页签，按当前游戏ID展示配置。待审核仅展示待审核方案；配置类型、审核状态、启用状态、名称、绑定字段和值点击查询后联合筛选。

操作编辑；待审核可通过/驳回均为演示，不调用真实接口

点击新增进入现有表单，取消返回列表。列表为固定演示数据，编辑、通过、驳回按钮仅展示并禁用；提交仅演示校验，不更新列表或执行审核。无匹配项显示「暂无数据」。

原型与安全边界

当前为静态交互原型。提交仅演示前端校验，不调用真实支付接口。各类型草稿只保留在页面内存中，刷新后恢复初始状态。

密钥和 Token 不上传、不写入浏览器存储或日志，敏感字段使用密码输入框。
