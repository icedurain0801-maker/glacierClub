需求说明

需求说明 · 配置审核

本页配置列表本次改动汇总

需求背景

配置项编辑提交后、审核通过前，存在一段审批真空期。此前系统会直接读取修改中的方案，导致正式线上环境的 SDK 方案丢失/裸奔，玩家侧读不到有效方案。

本次采用修改前原方案兜底策略：审核通过前，正式线上环境一律继续读取修改前的原方案（原数据）；只有审核通过后，新方案才正式顶替原方案、全量生效。即便是删除操作，在审核通过前也不生效，仍由原方案托底。测试 / 白名单环境则可提前读取新方案的草稿数据用于验证。

方案读取兜底逻辑

#方案归属配置当前状态实际读取方案逻辑说明与异常处理
1旧方案初始线上态无编辑 / 无审核旧方案（原数据）系统正常运转，直接读取当前已正式生效的线上方案。
2旧方案编辑 / 内测中正式线上环境 · 普通玩家旧方案（原数据）【核心兜底】保证正式线上绝对不裸奔，强制降级读旧方案。
3旧方案审核中正式线上环境 · 普通玩家旧方案（原数据）审批流程中的真空期，正式服由旧方案稳稳托底。
4旧方案审核不通过正式线上环境 · 普通玩家旧方案（原数据）审核未通过，正式线上无缝保持旧方案持续运行，确保业务不中断。
5新方案编辑 / 内测中测试 / 白名单环境新方案（草稿数据）允许测试服或白名单优先跑测新修改的草稿数据。
6新方案审核中测试 / 白名单环境新方案（草稿数据）审批真空期内，测试环境可继续验证新方案。
7新方案审核不通过测试环境 · 查看态新方案（被驳回的草稿）允许研发或运营在测试环境查看被驳回的草稿，以便基于此重新编辑。
8新方案审核通过所有环境新方案（正式生效态）流程顺利终结，新方案正式顶替旧方案，全量上线生效。
9旧方案方案被删除删除后未审核通过修改前的原方案（原数据）删除操作在审核通过前不生效，正式线上仍降级读取修改前的原方案兜底，绝不裸奔。

操作列 · 审核入口

  • 操作列去掉「刷新」，保留 编辑 / 审核 / 删除。
  • 每行新增 审核 入口，点击打开居中审核弹窗。
  • 「审核」文字右上角显示 待处理数量角标：数量为 0 隐藏，超过 99 显示 99+。
  • 左侧「配置中心」同步显示 全部待处理总数角标。

审核弹窗 · 申请列表

  • 第一屏即为申请表：申请ID、修改前数据、申请数据、申请时间、申请人、状态、操作。
  • 申请列表按申请时间倒序展示，最新申请置顶。
  • 每次编辑配置新增一条独立申请记录，不直接改主列表。
  • 只有「审核通过」的记录才展示修改前数据，其余状态为空。

两步审核流程

编辑新增申请→ 内测中→ 审核中→ 审核通过 · 写入主列表/ 审核不通过 · 主列表不变
  • 状态统一为：内测中 / 审核中 / 审核通过 / 审核不通过。
  • 「内测通过」点击时二次确认「是否确认内测通过？」，通过后才出现「审核」。
  • 点「审核」弹窗直接选择审核通过 / 审核不通过，不再跳详情页。
  • 审核通过 toast「审核已通过」，审核不通过 toast「审核不通过」，弹窗关闭。

主列表数据

  • 删除「原数据」列，「修改后数据」改名为 生效中数据。
  • 审核通过后，申请数据直接覆盖主列表「生效中数据」并置为生效中。
  • 审核不通过只标记该申请，主列表数据完全不变。

布局

  • 表格改为百分比列宽撑满内容区，消除右侧大片空白。
  • 操作按钮不换行、不贴边。
