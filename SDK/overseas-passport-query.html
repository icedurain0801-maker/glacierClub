需求说明 · 密保邮箱解绑 & 换绑 ×

1. 需求概述

背景：运营人员在通行证查询的「通行证安全信息」Tab 中，需要对玩家的密保邮箱执行后台级解绑或换绑操作，用于处理玩家申诉场景（邮箱失效、误绑、账号安全风险等）。

用户对象：游戏运营后台 — 具有「玩家信息编辑」权限的运营/客服人员。

2. 入口与触发条件

「通行证安全信息」Tab → 密保邮箱行 → 两个操作按钮：

  • 解绑 仅当玩家已绑定邮箱时显示；未绑定时隐藏。
  • 换绑 仅当玩家已绑定邮箱时显示；未绑定时隐藏。

3. 解绑弹窗

3.1 弹窗结构

字段类型必填说明
确认提示静态文本—「是否要解除 [邮箱] 和冰川通行证ID:[ID] 的绑定关系？」邮箱和ID从当前查询结果中读取，不可编辑。
解绑原因文本域 textarea必填运营人员填写操作原因，最多200字，供审计留存。

3.2 交互逻辑

  • 点击「解绑」按钮 → 弹窗打开，清空上次输入的解绑原因，邮箱/通行证ID自动填充。
  • 点击「确定」→ 校验解绑原因非空；若为空则在文本域下方展示红色提示「请填写解绑原因」，不关闭弹窗。
  • 校验通过 → 关闭弹窗，页面顶部 Toast 提示「申请解绑成功，待管理员审核」；密保邮箱行更新为「解绑申请中」状态，解绑/换绑按钮禁用。
  • 点击「取消」或右上角 × → 关闭弹窗，不做任何更改。

3.3 后续流转

解绑申请提交后，进入邮箱解绑审批页面的「待审核记录」队列，由审核人审批通过后方可真正解绑。

4. 换绑弹窗

4.1 弹窗结构

字段类型必填说明
冰川通行证ID静态只读—当前查询的通行证ID，自动回填。
当前绑定邮箱静态只读—当前密保邮箱，脱敏展示（如 li****yi@gmail.com）。
新绑定邮箱输入框必填运营填写新邮箱地址，需通过邮箱格式校验。不得与当前邮箱相同。

4.2 交互逻辑

  • 点击「换绑」按钮 → 弹窗打开，清空上次输入，自动填充通行证ID和当前邮箱。
  • 点击「确定」→ 依次校验：①新邮箱非空；②格式合法（标准邮箱正则）；③不与当前邮箱相同。任一不通过均在输入框下方红色提示对应错误。
  • 校验通过 → 关闭弹窗，Toast 提示「换绑成功，密保邮箱已更新」；密保邮箱行立即更新为新邮箱的脱敏展示。
  • 点击「取消」或 × → 关闭弹窗，不做任何更改。

5. 校验规则汇总

场景规则错误提示
解绑原因为空不允许提交请填写解绑原因
解绑原因超长≤ 200字原因不超过200字
新邮箱为空不允许提交请输入新绑定邮箱
新邮箱格式非法标准邮箱正则请输入正确的邮箱地址
新邮箱与当前相同不允许提交新邮箱不能与当前邮箱相同

6. 异常与边界

  • 无邮箱 密保邮箱字段为空时，解绑和换绑按钮均不展示。
  • 审核中 已有解绑申请待审核时，解绑/换绑按钮置灰不可点，Tooltip 提示「当前有解绑申请待审核」。
  • 权限 无「玩家信息编辑」权限的账号不展示解绑/换绑按钮。
  • 并发 确定按钮点击后立即置为 loading 状态，防止重复提交；接口返回后恢复。
  • 网络异常 接口失败时 Toast 展示红色提示「操作失败，请稍后重试」，弹窗保持打开，已填内容不丢失。
