灌水判定配置 — 需求说明
v3.1.3 2026-06-22 最新 ▼
1. 需求概述

背景 / 目标：社区积分体系催生大量灌水内容。本期在机审环节新增「灌水库规则审查」，作为机审的第三道关，对每条新发布内容跑 R1~R8 输出「正常 / 嫌疑 / 灌水」三档；被判「灌水」的内容在机审中作为「不通过」处理，备注自动填命中规则名称。

机审三道关（按优先级串行）：① 文本屏蔽词过滤 → ② 图片 / 视频阿里云云审查 → ③ 灌水库审查（本期新增，优先级最低）。前两道都通过才跑灌水检测；任一道未过则直接判不通过，不再往后跑。

边界：仅「灌水」在机审中视为不通过；「嫌疑」/「正常」视为机审通过。灌水检测仅对含文本（标题 / 正文 / 评论文字）的内容生效，纯图片 / 纯视频跳过。仅作用于新发布内容，不回溯历史。

2. 国内 vs 海外：机审结论的处置差异
  • 国内：机审结论仅作建议，所有内容全量过人工审核，是否对外由人工最终决定。灌水命中 → 机审建议拒绝 + 备注规则名 → 人工复核定夺。
  • 海外：机审结论直接决定是否对外。机审通过 → 直接对外；机审不通过（含灌水 spam）→ 直接拒绝、不对外，无人工兜底。
3. 配置能力
  • 总开关：关闭后灌水库审查不运行（机审仅保留屏蔽词 + 阿里云两道），已有打标数据不受影响。
  • 词库管理：维护灌水词库；支持单条添加与 CSV 批量导入（word 列）；可下载导入模板。词条列表每页 20 条分页展示（右下角「共 N 条 + 上一页 / 页码 / 下一页」，≤20 条仅显示「共 N 条」、页数多时页码以「首末页 + 当前页 ±1 + 省略号」收敛），并按添加时间倒序（最新在前）；单条添加或导入成功后自动回到第 1 页便于确认，删除导致当前页为空时自动回退到有效页。
  • 规则配置：R1~R8 每条可独立启用 / 禁用；灌水阈值（命中数 ≥ N 判「灌水」，默认 2）与嫌疑阈值（≥ M 判「嫌疑」，默认 1）可配，灌水阈值须大于嫌疑阈值。
  • 分版块：总开关、词库、规则、阈值均按所属版块各自配置，互不影响。

5. 功能逻辑要点
  • 优先级串行：屏蔽词 → 阿里云 → 灌水库，前序未过即短路返回，不再跑后序，灌水库永远是最后一道。
  • 灌水适用范围：只要内容含任何文本（标题 / 正文 / 评论文字）即跑 R1~R8；纯图片 / 纯视频无文本则跳过灌水检测。
  • 地区分流：国内机审仅建议、全量人工定夺；海外机审直接决定对外与否。
  • 备注受众：auditRemark 取规则名称（非编号）快照，多条按 R1→R8 顺序、以「、」连接，仅审核员可见。
  • 作者感知：作者可见自己内容被拒 / 审核中，但不显示具体命中规则（防绕过）。C 端提示文案统一为：「您的内容未通过社区规范审查」（帖子/动态/评论一致，不带「请修改后重新发布」避免评论场景歧义），需覆盖中 / 英 / 繁 / 韩四语言。
  • 联动：总开关关闭 / 规则停用 / 阈值调整均只对调整后的新内容生效，不回溯已判定内容。
6. 异常与边界
  • 灌水服务异常 / 超时：不阻断机审，灌水库这道降级为通过（屏蔽词与阿里云结论不受影响），避免误杀与卡死。
  • 命中规则为空却判为「灌水」：逻辑矛盾，按系统异常、不拦截。
  • 编辑后重判：帖子 / 动态编辑后重新提交，重跑完整机审三道关，覆盖旧的 spamStatus / 备注。评论不支持编辑，被拒后仅展示提示文案，无重判链路。
  • 多端一致：机审在服务端统一处理，App / H5 / 各语种版块结论一致。
  • 误杀兜底：「灌水」需命中 ≥ 灌水阈值（默认 2 条）方触发，单条短回复通常仅命中 1 条停在「嫌疑」，不会被灌水库拦截。
7. 数据分析

灌水判定结果的统计看板，用于评估规则效果与调参，仅查看、不参与线上判定。

  • 时间筛选：「近 7 天 / 近 30 天 / 近 90 天 / 自定义」四选一，默认「近 7 天」；选「自定义」时展开起止日期选择器，点「查询」刷新。
  • 分内容类型：「帖子」「动态」「评论」分三区各自统计。
  • 统计卡片：帖子 / 动态展示正常 / 嫌疑 / 灌水 / 合计；评论无「嫌疑」档（命中即灌水），仅展示正常 / 灌水 / 合计。各卡含数量、占比与占比条，万级数量做「万」单位中文化。
  • 分版块：统计随顶部「所属版块」切换，各版块数据独立。
  • 口径待对齐：占比按判定时点还是当前状态统计（国内人工把「灌水」改判通过后计入哪档）需产品确认。
8. 规则算法说明

所有规则以「字符分类」为基础：将内容按 Unicode 码点拆分，分为文字字符（中英文等）、数字字符、表情符号（emoji / 颜文字 / 平台自定义表情）、符号/标点/空白四类。有效字符 = 文字 + 数字。字符分类只跑一次，R1~R8 全部复用。

编号规则名称算法要点
R1词库命中 对内容做归一化（转小写 → 去空白/标点/表情/符号 → 合并连续重复字符），归一化串与词库 Set 做哈希查表（O(1)）。完全等于某词则命中；「包含」不算命中，靠 R1 不能绕过。
R2有效字数不足 取有效字符串，将连续相同字符合并为1个后计算长度（如「好好好的」→「好的」= 2），长度 < 配置阈值 N 则命中。
R3无文字内容 文字字符数 = 0 且数字字符数 = 0，即整条内容无任何可读文字或数字，则命中（如纯 emoji、纯标点）。
R4表情符号占比高 （表情符号数 + 符号/标点数）/ 总字符数 ≥ 配置阈值 P%，则命中。emoji 识别用 Intl.Segmenter + emoji-regex，避免漏判组合字符、肤色修饰。
R5单字符占比高 统计全部字符频次，取最高频单字符出现次数 / 总字符数 ≥ 配置阈值 Q%，则命中（如「啊啊啊啊」）。
R6整条复读 对有效字符串求最小重复周期（KMP failure 函数，O(L)）：若内容可被某子串整除且重复次数 ≥ 配置阈值 K 次，则命中（如「好的好的好的」周期=「好的」×3）。
R7纯数字 去除标点/符号/空白后，剩余字符全为数字字符（0-9 及全角数字），则命中（如「666」「8888」）。
R8键盘乱码 两路启发式，任一命中即触发：① 键位序列检测：有效字母串是否为键盘某行连续子串（正/反向，如 qwerty、asdfgh）；② 可读性检测：字母串中元音字母占比低于阈值，或连续辅音字符超过阈值（如 qwrtp）。R8 误判率最高，建议上线后单独观测命中样本。

推荐执行顺序（节省算力）：R3/R7 最便宜先跑 → R1 查词库 → R2/R4/R5/R6 计数统计 → R8 最贵放最后。词库一次性加载进内存 Set，O(1) 查表，后台更新后热刷新。
