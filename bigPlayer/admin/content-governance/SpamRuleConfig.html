灌水判定配置 — 需求说明
v3.1.3 2026-06-22 最新 ▼
1. 需求概述

背景 / 目标：社区积分体系催生大量灌水内容。本期在机审环节新增「灌水库规则审查」，作为机审的第三道关，对每条新发布内容跑 R1~R9 输出 normal / marked / spam 三档；被判 spam 的内容在机审中作为「不通过」处理，备注自动填命中规则名称。

机审三道关（按优先级串行）：① 文本屏蔽词过滤 → ② 图片 / 视频阿里云云审查 → ③ 灌水库审查（本期新增，优先级最低）。前两道都通过才跑灌水检测；任一道未过则直接判不通过，不再往后跑。

边界：仅 spam 在机审中视为不通过；marked / normal 视为机审通过。灌水检测仅对含文本（标题 / 正文 / 评论文字）的内容生效，纯图片 / 纯视频跳过。仅作用于新发布内容，不回溯历史。

2. 国内 vs 海外：机审结论的处置差异
  • 国内：机审结论仅作建议，所有内容全量过人工审核，是否对外由人工最终决定。灌水命中 → 机审建议拒绝 + 备注规则名 → 人工复核定夺。
  • 海外：机审结论直接决定是否对外。机审通过 → 直接对外；机审不通过（含灌水 spam）→ 直接拒绝、不对外，无人工兜底。
3. 配置能力
  • 总开关：关闭后灌水库审查不运行（机审仅保留屏蔽词 + 阿里云两道），已有打标数据不受影响。
  • 词库管理：灌水词库与恶意词库独立维护；支持单条添加与 CSV 批量导入（word 列）；可下载导入模板。
  • 规则配置：R1~R9 每条可独立启用 / 禁用；灌水阈值（命中数 ≥ N 判 spam，默认 2）与嫌疑阈值（≥ M 判 marked，默认 1）可配，灌水阈值须大于嫌疑阈值。
  • 分版块：总开关、词库、规则、阈值均按所属版块各自配置，互不影响。

5. 字段说明（审核记录新增 / 联动）
字段取值 / 说明
spamStatus灌水判定状态：normal / marked / spam，由命中条数与阈值决定
hitRules命中的规则编号数组，如 ["R2","R5"]
machineResult机审结论：通过 / 不通过。屏蔽词、阿里云、灌水三道任一不过即不通过
machineFailReason机审不通过的原因来源：屏蔽词 / 阿里云 / 灌水库，定位是哪道关拦截
auditResult最终结论。国内由人工置通过 / 拒绝；海外直接取 machineResult
auditRemark审核备注（仅 B 端审核员可见）。灌水拦截时填命中规则名称快照，如有效字数不足、单字符占比高（多条以、连接）
contentType内容类型：帖子 / 动态 / 评论，三类统一适用
6. 功能逻辑要点
  • 优先级串行：屏蔽词 → 阿里云 → 灌水库，前序未过即短路返回，不再跑后序，灌水库永远是最后一道。
  • 灌水适用范围：只要内容含任何文本（标题 / 正文 / 评论文字）即跑 R1~R9；纯图片 / 纯视频无文本则跳过灌水检测。
  • 地区分流：国内机审仅建议、全量人工定夺；海外机审直接决定对外与否。
  • 备注受众：auditRemark 取规则名称（非编号）快照，多条按 R1→R9 顺序、以「、」连接，仅审核员可见。
  • 作者感知：作者可见自己内容被拒 / 审核中，但不显示具体命中规则（防绕过），仅给笼统提示文案。
  • 联动：总开关关闭 / 规则停用 / 阈值调整均只对调整后的新内容生效，不回溯已判定内容。
7. 异常与边界
  • 灌水服务异常 / 超时：不阻断机审，灌水库这道降级为通过（屏蔽词与阿里云结论不受影响），记录失败日志并告警，避免误杀与卡死。
  • 命中规则为空却判为 spam：逻辑矛盾，按系统异常、不拦截，并告警排查。
  • 编辑后重判：内容编辑后重新提交，重跑完整机审三道关，覆盖旧的 spamStatus / 备注。
  • 多端一致：机审在服务端统一处理；海外作者的被拒提示文案需覆盖英 / 繁 / 韩。
  • 误杀兜底：spam 需命中 ≥ 灌水阈值（默认 2 条）方触发，单条短回复通常仅命中 1 条停在 marked，不会被灌水库拦截。
8. 待澄清（开发前需对齐）
  • 评论现有是否有机审 / 审核流？三类内容是否共用同一机审链路？（若评论原无审核流，本期对评论为「新增」而非「接入」）
  • 被拒内容的发帖经验值是否发放 / 扣回？是否计入用户发帖数？
  • 海外机审不通过是否对作者开放申诉入口？（海外无人工兜底，需明确申诉链路）
