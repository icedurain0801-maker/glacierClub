灌水判定配置 — 需求说明
v1.1.0 2026-06-22 最新 ▼
1. 需求概述

背景 / 目标：v1.0.0 仅对内容做 normal / marked / spam 打标，不触发任何动作。本期将 spam 判定结果接入内容审核流程：当一条帖子 / 动态 / 评论被判定为灌水（spam）时，系统在审核环节自动给出机审拒绝结论，审核备注自动填入命中的规则名称，供人工复核与申诉追溯。

边界：仅 spam 触发机审拒绝；marked（嫌疑）与 normal（正常）不拦截，仍走原有审核流程。本期仅作用于新发布内容，不回溯历史数据。

用户对象：① 系统（自动判定与打标）；② 内容审核 / 运营人员（查看机审结论、备注，处理申诉）。

3. 字段说明（审核记录新增 / 联动）
字段取值 / 说明
spamStatus判定状态：normal / marked / spam，由命中条数与阈值决定
hitRules命中的规则编号数组，如 ["R2","R5"]
auditResult审核结论。spam 时自动置为机审拒绝；其余维持原结论（待审核 / 通过等）
auditRemark审核备注。机审拒绝时自动填入命中规则名称，如有效字数不足、单字符占比高（多条以、连接）
auditType审核方式：机审 / 人工。本场景为机审
auditTime机审判定的时间戳，与内容提交近实时
contentType内容类型：帖子 / 动态 / 评论，三类统一适用
4. 功能逻辑要点
  • 触发时机：插在「发布提交成功之后、内容对外可见之前」，机审拒绝的内容不进入公开展示。
  • 备注规则：auditRemark 取 hitRules 对应的规则名称（非编号），多条按 R1→R9 顺序、以「、」连接，便于审核人员直读。
  • 总开关联动：内容治理总开关关闭时，不跑判定、不产生机审拒绝，所有内容走原审核流程。
  • 规则联动：被停用的规则不参与命中计数，自然不会出现在 hitRules 与备注中。
  • 阈值联动：调整灌水阈值会改变 spam 的判定口径，进而影响机审拒绝的触发范围；调整仅对调整后的新内容生效。
  • 分版块：判定与拒绝口径按内容所属版块各自的配置执行。
5. 异常与边界
  • 判定服务异常 / 超时：不阻断发布，该内容降级为不拦截（走原审核流程），记录失败日志，避免误杀与发布卡死。
  • 命中规则为空却判为 spam：逻辑矛盾，按系统异常处理、不拒绝，并告警排查。
  • 人工复核优先级：机审拒绝后人工可二次改判，人工结论覆盖机审结论，auditType 更新为「人工」，保留原 hitRules 供追溯。
  • 申诉：用户对机审拒绝可申诉，进入人工队列；申诉通过则内容恢复可见。
  • 编辑后重判：内容被编辑后重新提交，按编辑后的内容重新跑判定，覆盖旧的 spamStatus / 备注。
  • 多端一致：判定与拒绝均在服务端统一处理，App / H5 / 各语种版块结论一致。
  • 误杀兜底：spam 需命中≥灌水阈值（默认 2 条）方触发，单条短回复通常仅命中 1 条停在 marked，不会被机审拒绝。
v1.0.0 2026-06-18 ▼
背景与目标

社区积分体系催生大量灌水内容。本期只做「判定」，不做惩罚：对每条新发布内容输出 normal / marked / spam 三档状态标记。

总开关
  • 关闭后所有判定规则停止运行，已有打标数据不受影响。
词库管理
  • 灌水词库与恶意词库独立维护，互不影响。
  • 支持单条输入添加与 CSV 批量导入（word 列）。
  • 下载导入模板可获得标准格式示例。
规则配置
  • R1~R9 每条规则可独立启用/禁用。
  • 灌水阈值：命中规则数 ≥ N 判定为 spam（默认 2）。
  • 嫌疑阈值：命中规则数 ≥ M 判定为 marked（默认 1）。
  • 灌水阈值必须大于嫌疑阈值。
