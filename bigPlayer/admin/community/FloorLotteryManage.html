需求说明
楼层抽奖管理 — 需求说明
v3.1.0 2026-05-18 最新 ▼
本次变更

楼层抽奖新增/编辑页新增「发奖方式」字段，支持自动发奖模式；列表页同步新增该字段列。

背景 & 目标

当前活动截止后全部依赖人工介入发奖，效率低、易漏发、时效性差。自动发奖模式由系统在截止时刻自动完成抽取和发奖，降低运营人力成本。

字段定义
  1. 影响位置：新增页 / 编辑页 / 列表页 NEW
  2. 字段类型：单选
  3. 选项：
    • 人工审核 默认 — 沿用现有流程，运营手动操作发奖
    • 自动发奖 — 系统在活动截止时刻自动执行抽取 + 发奖
  4. 列表展示：新增「发奖方式」列，用标签区分两种模式
自动发奖触发逻辑
  1. 触发时机：活动截止时间到达，由定时调度任务触发
  2. 参与范围：截止时刻前已达标（满足楼层条件）的玩家
  3. 操作：从达标玩家中随机抽取，按中奖人数 N 发放
设中奖人数 = N，已达标人数 = M
实际发奖人数 = min(N, M)
⚠️ 若 N > M，只发放 M 个，剩余名额不补发，活动正常结束。
临界 & 异常场景
  1. 边界 M = 0（无人达标）：发奖人数为 0，活动置「已结束·无中奖」，不报错不重试
  2. 边界 N = 0（中奖人数为 0）：前端校验拦截；绕过写入时，调度检测 N≤0 跳过发奖并记录日志
  3. 边界 N ≤ M（达标人数充足）：N < M 时随机抽取 N 人；N = M 时全部达标玩家均中奖；均属正常发放
  4. 边界 截止时刻并发写入：以截止时刻前已落库的达标记录为准，之后的提交不参与本次抽取
  5. 边界 活动进行中修改发奖方式：允许在未进入发奖流程前修改，变更立即生效；进入发奖流程后锁定
  6. 边界 活动截止时间被提前：调度任务以最新截止时间重新调度，旧任务取消
验收标准
  1. 新增/编辑页有「发奖方式」字段，默认「人工审核」，可切换
  2. 列表页有「发奖方式」列，正确展示两种标签
  3. 选自动发奖 + 活动截止后，系统自动抽取 min(N,M) 名玩家发奖
  4. M=0 时活动正常结束，不报错
  5. N>M 时仅发 M 个，不补发
  6. 重复触发不重复发奖
  7. 已发奖后发奖方式字段不可编辑
