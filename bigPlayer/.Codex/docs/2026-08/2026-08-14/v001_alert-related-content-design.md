# 告警关联原文完整展示设计

日期：2026-08-14

## 背景

风险告警详情已经通过 `related_contents` 返回关联帖子和评论，但关联内容查询缺少平台作者 ID，详情区域也没有按字段完整展示原文信息。需要让处置人员能够直接核对原文、作者身份和发布时间。

## 目标

在正式公共舆情系统的告警详情中，逐条展示关联内容的内容类型、完整原文、作者、作者 ID、发布时间和来源链接，并保留无关联内容时的空状态。

## 范围

### 包含

- 正式后端告警详情查询补充 `platform_author_id`，接口映射为 `author_id`。
- 告警详情抽屉逐条渲染帖子和评论。
- 展示 `content_type`、`title`（有值时）、完整 `body`、`author_name`、`author_id`、`published_at`、`source_url`。
- 补充 repository 与路由测试，覆盖帖子、评论、作者 ID、完整正文、空关联和不存在告警。

### 不包含

- 不新增数据库迁移或修改已有表结构。
- 不修改独立的 `public-opinion-server` 原型服务。
- 不改变告警生成、关联规则、处置状态或钉钉推送逻辑。

## 数据设计

`GET /alerts/:id` 继续返回 `related_contents` 数组。每项保留现有字段，并新增：

```json
{
  "author_id": "平台作者 ID"
}
```

数据库字段使用已经存在的 `po_contents.platform_author_id`。帖子和评论使用同一返回结构，通过 `content_type` 区分。

## 展示设计

关联原文区域按数组顺序渲染独立内容块。每块包含：

- 类型：映射为“帖子”或“评论”。
- 标题：有值时展示。
- 原文：完整正文，不截断；长文本换行。
- 作者：作者名称；为空时显示占位文本。
- 作者 ID：平台作者 ID；为空时显示占位文本。
- 发布时间：原始发布时间；为空时显示占位文本。
- 来源链接：有值时提供可点击入口；为空时不显示链接。

关联数组为空时继续显示“暂无关联原文”。单条字段缺失不影响同条其它字段展示。

## 实现边界

后端只调整 `getAlert` 对关联内容的 SELECT 和返回映射；前端只调整告警详情关联内容渲染。沿用现有接口、抽屉和样式体系，避免引入新的状态管理或数据模型。

## 测试策略

- repository 测试：验证关联内容查询返回 `author_id`，并保留帖子、评论和空关联覆盖。
- 路由测试：验证 `GET /alerts/:id` 返回完整正文、内容类型、作者、作者 ID、发布时间和来源链接。
- 回归验证：确认不存在告警仍返回 404，处置 PATCH 行为不变。

## 验收标准

1. 告警详情关联原文区域不再只显示摘要或空提示，而是逐条列出帖子/评论。
2. 每条内容均可看到完整正文、作者、作者 ID 和发布时间。
3. 作者 ID来自数据库已有平台作者字段，不需要新增迁移。
4. 帖子和评论能明确区分，空字段和空关联有稳定占位表现。
5. 相关测试通过，且未改变告警处置流程。
