小游戏支付切换后台（评审版）

单方案：按后台配置周期滚动计算 target / safe_target / gap，仅用 safe_target 判定是否切内购。充值接口只读缓存结果，不做重计算。

方案总览（只保留方案1）

统一指标：target = android_period × 阈值%，safe_target = target × 安全垫比例 + 固定安全垫，gap = safe_target - ios_iap_period。

  • 优先级 1 自然量新用户累计充值 500元以内 强制走内购（最高优先级）。
  • 优先级 2 水位线补差：gap > 0（未达 safe_target）强制内购，gap ≤ 0 切回网页。
  • 优先级 3 命中最小持有时间：已在内购状态且未到持有时长，继续维持内购，避免短时反复切换。
  • 优先级 4 其余情况走网页支付；缓存缺失或统计异常按回退策略执行。

评审示例（多场景）

示例按当前配置自动演算，便于项目组评估“切换频率”和“手续费”平衡。

场景 安卓滚动流水 iOS内购滚动流水 用户特征 命中规则 返回渠道 说明

后端落地方案（具体实现）

  1. 统计任务按 stat_agg_minutes 聚合，计算最近 window_hours 内安卓与iOS内购流水。
  2. 决策任务按 refresh_minutes 读取最新统计值，计算 gap 并更新路由缓存。
  3. 安卓统计口径固定为 wxgame + bankCode，iOS统计口径固定为 wxgameios。
  4. 聚合键：game_id + bank_code + paid_time，并过滤测试账号和 test 标签订单。
  5. 统一指标：target = android_sum × threshold_ratio，safe_target = target × safety_factor + safety_fixed_amount。
  6. 缺口指标：gap = safe_target - ios_iap_sum；gap > 0 走内购，gap ≤ 0 走网页。
  7. 结果写入 Redis：payment:route:{gameId}:{bankCode}，充值接口仅读该 key（O(1)）。
  8. 缓存过期/查询失败时按 fallback_policy 回退，不在充值链路走数据库重算。
  9. SDK 只需要透传后台路由结果，前端不参与逻辑判断。
