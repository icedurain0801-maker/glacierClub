# 舆情区域、游戏与社区分层设计

## 目标

将舆情分析从单一游戏维度扩展为“区域 → 游戏 → 社区”的独立归属体系，支持同一游戏拥有多个版本、地区服或运营社区，并保证抓取、分析、告警、关键词和任务记录按社区隔离。

首批主数据：

- 境内 / 超能世界 / 超能世界国服版
- 境外 / Last Night / 暂无社区

现有抓取数据统一迁移到“境内 / 超能世界 / 超能世界国服版”。Last Night 只作为空数据游戏存在，不创建社区、采集源或内容。

## 当前实现与问题

舆情后台由 `admin/PublicOpinion` 下的多页静态 HTML 和原生 JavaScript 组成，后端为 `public-opinion-system/server`。当前数据表和接口主要依赖 `game_id`，没有区域和社区字段。Q1 连接器中的平台 `gameId`、`gameVersion` 只用于平台请求，不能替代后台业务社区对象。

当前主要缺口：

- 同一游戏的不同社区无法独立归属和筛选
- 没有境内/境外隔离
- 采集源、内容、告警、关键词和任务只能按游戏过滤
- 六个页面的游戏筛选范围和联动行为不完全一致
- 概览部分告警查询没有套用同一游戏筛选条件
- 历史数据没有社区归属

## 数据模型

新增 `po_communities` 社区主表：

- `id`
- `game_id`
- `region_code`：`domestic` / `overseas`
- `name`
- `status`：`enabled` / `disabled`
- `sort_order`
- `created_at`
- `updated_at`

约束：

- 社区名称在同一游戏下唯一
- 社区软停用，不删除历史数据
- 停用社区不能新建采集任务，但允许查询历史数据和重新分析历史内容

现有表增加社区归属：

- `po_sources.community_id`
- `po_accounts.community_id`
- `po_contents.community_id`
- `po_alerts.community_id`
- `po_keyword_rules.community_id`

`game_id` 保留，用于游戏级聚合、旧接口兼容和一致性校验。同步运行、分析任务等通过 source/account/content 继承社区，不重复添加无必要字段。

服务端写入校验：

- 社区存在且属于当前游戏
- 新任务使用的社区处于启用状态
- source、account、content 的 game/community 归属一致
- 抓取链路从 source/account 继承归属，前端筛选参数不能覆盖真实归属

## 页面与交互

新增“社区管理”入口，支持按区域和游戏查看社区树，并完成社区新增、编辑、启停、排序。列表显示采集源数量、内容数量和最近抓取状态。停用前提示绑定的采集源和影响范围。

六个现有舆情页面统一使用联动筛选：

**区域 → 游戏 → 社区**

- 支持“全部区域”“全部游戏”“全部社区”
- 切换上级筛选时清空无效下级选项并重新请求
- 未选社区时，在当前区域/游戏范围内汇总全部社区
- 概览页可以记住上次筛选
- 游戏切换后刷新社区、采集源和账号选项

页面调整：

- 舆情数据概览：指标、趋势、来源、热点和告警按当前范围统计，显示完整归属路径；无社区时显示明确空状态
- 抓取内容管理：列表和详情显示区域/游戏/社区，筛选与分页总数同口径
- 风险告警管理：按社区筛选，详情显示归属，聚合和去重按社区隔离
- 抓取账号管理：新增采集源必须选择区域、游戏、社区；停用社区下的源不可启动同步
- 抓取任务记录：支持社区筛选，历史任务保留原社区快照语义
- 监控关键词设置：规则按社区保存；支持复制社区规则到另一社区

社区不可在现有采集源上直接切换，以防历史数据被重新归类；需要调整归属时停用旧源并新建绑定正确社区的源。

## API 兼容

现有只传 `gameId` 的请求继续可用，解释为游戏级汇总。新增筛选参数：

- `regionCode`
- `communityId`

筛选规则：

- `communityId` 存在时按社区查询，并校验其属于指定游戏
- 没有 `communityId` 时按 `regionCode + gameId` 汇总
- 只有 `gameId` 时汇总该游戏全部社区
- 三者都没有时按权限范围返回全部数据

需要覆盖的查询和写入链路包括 games、communities、sources、accounts、contents、overview、alerts、sync-runs、keyword-rules、analysis backfill 和 source/account sync。

## 数据流与分析

```text
采集源 / 账号
  ├─ game_id
  └─ community_id
        ↓
抓取内容
  ├─ game_id
  └─ community_id
        ↓
分析任务、分析结果、告警、抓取记录
```

AI 分析上下文加入游戏名、社区名、区域和语言信息；分析缓存键包含 `community_id`。关键词规则、告警聚合、告警去重和钉钉路由均按社区隔离。历史内容重新分析时保留原社区。

## 历史迁移

迁移脚本必须可重复执行：

1. 创建或获取“超能世界国服版”社区
2. 将现有超能世界采集源绑定该社区
3. 回填账号、内容、告警和关键词规则的社区字段
4. 校验 game/community/source/account 一致性
5. 创建或获取 Last Night 游戏
6. 不创建 Last Night 社区、采集源或内容
7. 输出迁移统计和无法归属记录

无法判断归属的数据不能自动归入境内统计；迁移应失败并列出待处理记录。唯一约束和条件更新保证重复执行不重复创建或污染数据。

## 空数据与停用规则

Last Night 在游戏列表中显示为境外游戏；社区列表显示“暂无社区”。概览、内容、告警和任务记录显示明确空状态，不创建虚拟社区、不生成虚假采集源或任务。

停用社区不会删除历史数据；历史数据可查询、可重新分析，但不能新增同步或采集任务。

## 测试与验收

后端测试覆盖：

- 社区 CRUD、同游戏重名校验和停用
- 区域/游戏/社区筛选组合
- source/account/content 归属一致性
- 停用社区禁止采集
- overview、contents、alerts、sync-runs、keyword-rules 按社区隔离
- 内容列表和分页总数同口径
- 迁移脚本可重复执行
- Last Night 无社区时返回空状态

前端测试覆盖：

- 区域到游戏到社区的联动
- 上级切换清空失效下级值
- 六个页面筛选器一致
- 停用社区按钮状态和提示
- Last Night 空状态
- 旧 `gameId` URL/接口兼容
- 详情显示完整归属路径

验收标准：

1. 所有现有超能世界数据显示为“境内 / 超能世界 / 超能世界国服版”。
2. 新增社区后可独立配置采集源、关键词、内容和告警。
3. 同一游戏不同社区的数据不互相混入。
4. 境内和境外数据不互相混入。
5. Last Night 没有社区时保持干净空状态。
6. 停用社区不删除历史数据。
7. 旧链接和只带 `gameId` 的调用继续工作。
8. 抓取、分析、告警和任务记录的筛选口径一致。
