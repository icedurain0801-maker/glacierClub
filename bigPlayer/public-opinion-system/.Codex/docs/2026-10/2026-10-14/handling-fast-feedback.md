# 单条与批量内容处理保存提速

Status: released-and-accepted
Date: 2026-10-14

截图中的单条处理保存接口为 POST /contents/batch-handle。本地事务和审计提交后，原接口仍等待 BaaS 全量读取、写锁及整批元数据发布；保存成功的页面随后重新加载列表和统计。此次延续此前优质审核提速方案，将云端同步排入现有串行合并/失败重试调度，本地事务成功即返回。事务失败不会触发同步或显示保存成功。

修改 server/src/app.js、server/src/services/baasReadRepository.js：处理状态以本地已提交记录为准，BaaS 内容正文及分析数据仍按现有读取路径。处理记录快照共用 1 秒缓存，提交后立即失效；在提交前发起的旧查询不能恢复旧缓存。处理状态在列表筛选、分页、详情、统计前统一叠加。云端数据和本地处理记录读取失败仍返回错误，不回退到旧状态。

修改 ../admin/PublicOpinion/assets/content-handling.js、assets/content.js、content.html：单条和批量成功响应后直接更新当前页状态/备注，待处理筛选中移除已处理行；同步调整当前页相关风险计数，后台再校准统计。按钮保存中禁用，失败保留输入；不等待全列表重载，提交前开始的旧列表/统计响应不能覆盖保存结果。更新两份 JS 缓存版本到 20261014-handling-fast-r1。

新增 server/test/handlingFastFeedback.test.js 和 .tests/2026-10/2026-10-14/handling-fast-browser.cjs。24 项 HTTP/云端读模型/处理筛选测试通过：等待本地提交、云端不阻塞响应、失败不调度、读取并发、处理状态筛选与计数、成员范围、后台失败重试。候选包再次通过同 24 项；可见 Edge 使用候选实际前端及 API 通过单条/批量、保存失败保留输入、禁止重复提交、备注 HTML 转义、状态即时更新、等待统计期间计数保持、待处理筛选移除、刷新保留状态和 390px 视口。单条 280ms、批量 265ms，均含模拟的 200ms 保存延迟；此为隔离测试耗时，正式性能待上线验收。

候选包从切换前现役 API 和前端克隆，逐段覆盖本次修改，保留现有紧急告警统一名称、L3 独立复核、登录、优质审核提速及其他代码。API 423 文件、前端 46 文件 manifest 校验通过。候选、服务 XML 快照及带回滚的默认 dry-run 切换脚本位于仓库根 .temp/handling-fast-20261014/，不得提交敏感服务快照。用户批准后已切换 API 与前端。

正式验收：本机 API、前端与正式 HTTPS 前端 health 均 200，两个服务均 Running。通过已登录的正式可见 Edge，对已处理内容 927726 重保存其原处理方式和原备注，未改变业务处理结论；保存接口与页面均 200，117ms 完成页面反馈，刷新后仍显示“已处理”，浏览器脚本错误为零。该重保存会更新既有审计时间，除此之外历史数据未改，未重分析、未通知。Git 不提交、不推送。
