# BaaS 读取鉴权故障排查

- 时间：2026-10-14 14:15 北京时间。
- 状态：14:26 已恢复；此前 BaaS 拒绝后台已有访问凭据。
- 用户现象：抓取内容管理显示“社区加载失败，请重试”，随后列表显示“当前地区暂无可用社区”。

## 已验证

1. PublicOpinionApi、PublicOpinionFrontend3001 均为 Running；本机 `/health` 返回 HTTP 200。
2. `/api/public-opinion/communities?regionCode=domestic` 返回 HTTP 503，错误码 `BAAS_DATA_UNAVAILABLE`。
3. 读取凭据对 BaaS `/v1/auth/me`、`/v1/collections/po_read_metadata_v1/docs/current` 串行各探测 4 次，均返回 HTTP 401，平台提示需要登录。
4. 读取与写入使用的现有 DPAPI 凭据相同，签发时间为 2026-10-14 11:13:46，过期时间为 2026-11-13 11:13:46（北京时间），尚未到期。钉钉既有授权凭据调用身份接口同样返回 401。
5. BaaS 控制台显示应用仍启用，有 6,651 条文档。该数量只能证明控制台可见文档存在，不能证明每条业务数据完整。
6. 已通过真实浏览器复现社区加载失败。

## 结论和边界

直接故障点是 BaaS 拒绝后台凭据，导致云读取失败。更早个别元数据探测曾成功，目前已连续失败；是否平台签名配置变化、会话撤销或其它鉴权问题，仍待平台核实，不能据此断言密钥过期或数据删除。

未修改鉴权、权限、数据源或生产配置，未删除数据，未重启服务，未提交或推送 Git。后续需通过受支持授权流程取得有效后台凭据，或由平台修复鉴权；恢复后须验证社区、列表、统计和钉钉授权，不能仅验证健康检查。

以上为首次排查状态；后续恢复操作和验证如下。

## 恢复方案与变更

现有登录管理员的身份验证仍成功。后台授权与登录会话保存分离，旧后台 token 被拒绝后无法续接有效会话。

- `server/src/services/baasDingTalk.js`：新增已有授权的同账号续接。仅允许已验证的同一实名管理员更新已有后台授权；普通用户、其他管理员、待角色映射身份均不续接。写入前仍调用 BaaS 身份接口校验。
- `server/src/app.js`：启用云端读取时，在管理员登录会话验证中尝试上述续接。失败只记录错误码，不输出凭据，不绕过正常身份验证。
- `server/src/services/baasDataClient.js`：只针对两个既有数据凭据路径选择更新的 AES-GCM 加密后台授权，要求账号相同、凭据有效期未过且授权时间晚于 DPAPI 文件修改时间。密文异常或账号不一致保留原凭据；实际请求仍由 BaaS 校验签名和 ACL。
- `worker/src/baasLiveWriter.js`：云端同步共用上述凭据读取逻辑。
- `server/test/baasServiceRenewal.test.js`：覆盖同账号续接、跨账号拒绝、过期/损坏/较旧凭据回退、平台拒绝时禁止保存。

API 从当前现役副本定向叠加修改，切换至 `api-release-20261014-baas-auth-recovery-r1`，仅重启 API 服务。同步计划任务保留原频率、身份、状态和数据范围，仅将执行入口切换至 `baas-live/releases/release-20261014-auth-recovery-r1`，使用恢复后的 API 依赖包。未修改 Worker 采集/分析任务，未手动补发通知，未提交或推送 Git。旧运行包及服务配置备份保留用于回退。

## 剩余边界

BaaS 为什么使尚未到期的旧 token 失效仍未确定。本次修复使同一已授权管理员登录时能够安全续接有效凭据；如果平台同时拒绝登录和后台凭据，仍需要正常重新登录或由平台恢复鉴权，不能绕过。未发送钉钉测试消息，本次仅恢复其已有后台授权。
