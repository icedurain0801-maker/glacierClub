## 设计边界

1. 云同步使用三张表的时间覆盖索引增量读取，按已导入 ID 过滤、逐 ID 合并最大变化时间，再按全局 changed_at/id 排序取最早一页；游标仅在云写确认后推进，不减少社区或数据。小批 ID 方案实测435秒，已弃用，时间覆盖方案106–209毫秒。
2. 通知先按 run/parent 索引得到成员，再关联内容；消除大表 OR 驱动退化。保持今天/昨天补推限制、发送回执和权限口径，不触发手动推送。
3. 列表先物化分页 ID，再取正文和分析大字段；丰富筛选、日期、分页稳定顺序、总数及删除口径不变。计数、汇总用覆盖索引和有界并发，避免扫描大量 JSON。
4. 保持所有鉴权、处理和审核实时语义，不通过旧缓存、延长超时或隐藏数据解决性能问题。
5. 每项按旧结果对照和隔离测试；从现役包定点构建，保留并行修改和回滚；三页筛选、切社区、翻页、并发浏览器回归。

备选仅改前端不能解除共享数据库竞争；增大超时不减少查询成本，均不采用。涉及新索引或取消运行中查询时先说明并确认具体影响，不沿用上次索引维护授权。
