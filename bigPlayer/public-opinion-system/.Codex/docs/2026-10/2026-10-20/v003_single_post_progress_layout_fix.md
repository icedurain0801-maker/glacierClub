# 单帖分析进度样式修复

日期：2026-10-20

## 原因

现役前端新 JS 包含进度节点，但原 HTML 仍引用旧 CSS，现役 CSS 不含进度样式，导致进度条不可见、文字黏连。此前浏览器使用本地资源自测未覆盖现役发布文件的一致性。

## 变更

- 新增独立 `single-post-progress.css`，HTML 显式引用并更新 JS 缓存版本。
- 进度区使用紧凑双列布局：状态和数量在上方，抓取/分析两条进度在下方；窄屏改为单列。
- 定位帖子只展示搜索条；总量未知时显示动态条且不伪造百分比。
- 保留指定内容提取链路，名称显示“按要求提取”，不改变业务处理。
- 排队无动画，失败停止动画，部分完成用橙色，完成用绿色。

## 验证

Edge 浏览器加载真实页面源码与本地候选资源，使用隔离接口完成 9 组检查：CSS 计算高度 8px、对齐、搜索单条、排队、抓取、分析 160/207=77.3%、窄屏、失败、指定提取部分完成。无页面脚本错误，未创建真实采集任务。语法/空白检查通过。

证据：`.tests/2026-10/2026-10-20/progress-layout-r2-browser.json` 与 `progress-analysis-layout-r2.png`。

候选以现役 `release-20261020-facebook-resume-front-r1` 为基线，仅合入 HTML、进度渲染 JS、独立 CSS。其余前端、API、Worker、登录服务不变。已发布到 `release-20261020-keyword-quality-progress-front-r1`，前端服务运行正常。Edge 通过 `http://127.0.0.1:3001/admin/PublicOpinion/single-post-analysis.html` 验证 HTML、JS、两个 CSS 均实际加载；真实域名根路径会按现役路由重定向到概览，因此未用该路径作为单帖验收入口。
