# 降低负面待处理门槛，补齐游戏机制投诉识别

## 需求与现状

用户要求降低负面待处理门槛，关注级用于轻微、可处理也可不处理的负面表达；对游戏机制的明显质疑应进入负面待处理。适用于国内/海外所有平台的帖子、动态、评论和回复，概览与抓取内容管理使用同一算法且集合互斥。

源码 `server/src/services/riskSeverityNormalizer.js` 当前分数升级要求negativeScore≥0.60且confidence≥0.60；游戏问题命中可直接升级，但主要覆盖故障、异常、资产及服务错误，对公平性、匹配机制、奖励价值等语义覆盖不足。截图未提供confidence，当前实际运行版本、完整内容及写入路径尚未核实；不可断言86%仍关注的唯一原因是置信度。

## 用户已弹窗拍板的新规则

2026-10-10，用户在Codex会话弹窗选择“采用推荐规则：游戏投诉直接进入＋其他负面≥50%（推荐）”。本节为定稿，供开发与测试直接执行。

优先级从上到下，最终只取一个等级：

| 条件 | 最终结果 |
|---|---|
| 正面 | normal；不能由负面分数、关键词或推荐字段升级 |
| 负面，已有urgent | 保持urgent，不因新阈值降级 |
| 负面，明确抱怨/质疑游戏玩法、机制、公平性、匹配、平衡/数值、奖励/掉落、概率、活动、功能bug、登录、付费或服务体验 | urgent，即负面待处理；不另加分数或confidence门槛 |
| 其他负面，negativeScore≥0.50 | urgent；confidence用于记录和质量评估，不作为拦截条件 |
| 其他负面，negativeScore<0.50且无明确需处理问题 | attention，即关注级 |
| 中性或缺少可信分析结果 | 保持既有规则；不因提到游戏机制就升级，不把缺失结果伪装为已分析 |

分数表示系统负面评分，不表述为客观概率。具体识别须结合正文语义：明确不满、质疑不公、损失或体验问题才适用游戏投诉规则，普通攻略/问题咨询/正面分享不因“匹配”“概率”等单词升级。补全文或上下文时不得把父帖负面等级强制继承给评论。英语等海外内容遵守相同语义规则。

此规则替代通用负面原先“60%负面分数且60%confidence”的双门槛。关注级与负面待处理仍互斥，正面归正常优先。

## 实现与数据要求

- 模型提示词、系统最终归一化、轻/深分析及缓存/写入入口一致；不只在前端改标签，也不靠关键词堆叠模拟语义分类。
- 对存量重新分类：分数已满足新规则的可确定性归一化；游戏语义缺失的走现有分析流程，对完整内容重新判断。保留原始结果与版本/原因/批次审计，不能批量把全部negative无条件改urgent。
- 修改前先核实实际运行构建与样本记录，区分代码算法缺口、存量未纠偏和运行旧版；新规则不替代对既有缺陷的排查。
- 列表、详情、数量、概览负面待处理/关注级全部采用同一最终等级；数据修复后用户当前筛选可看到变化；两个集合不得重叠。
- 与`defect-positive-content-in-attention.md`衔接：正面归正常约束始终优先，本需求定稿后替代前件“不调整负面阈值”的范围限制，仅扩大本件授权范围。
- 负面待处理分类与当前告警/通知沿用现有关联规则。本需求不自动触发历史钉钉或其他外部通知补发；新分类后新增告警数量影响须由项目经理核实并报告，避免历史回算引发通知轰炸。
- 不删除内容、分析或历史告警，不改变采集器/调度频率；数据修复、运行切换按已有岗位权限办理。
