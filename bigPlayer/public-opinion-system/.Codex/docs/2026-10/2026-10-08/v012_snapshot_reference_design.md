# 可核对的同快照备份方案

Status: isolated-demo-passed-pending-independent-review

## 结论与方案选择

现有 `mysqldump --single-transaction` 在它自己的数据库连接上建立一致读视图；另一连接稍后执行的 `COUNT(*)` 或摘要不会自动共享该视图。持续写入时，不能把两个结果称为同一快照。MariaDB 10.4.14 的隔离演练已经直接证明两个连接会得到不同内容。

选择方案 A：在批准且已排空写入者的窗口内，由专用连接持有 `FLUSH TABLES WITH READ LOCK`，先在该锁下生成源端精确逐表计数和分块摘要，再在锁仍持有时由独立连接执行 `mysqldump --single-transaction`，导出退出 0 后重做源端计数/摘要，比较前后相等才释放锁。恢复端在全新隔离实例计算相同清单，逐项比较。这样无需假设两条连接的 InnoDB snapshot 相同，而是用全局读锁保持数据不变，锁内前后清单约束了整个导出时间段。

备选方案 B：仅停应用写入者，先算源端清单，再执行 dump。锁负担较小，但未证明其他数据库连接、计划任务或手工操作不会写入；需要额外的数据库级写入禁令和旁路审计，现阶段不推荐。备选方案 C：只用 mysqldump 单连接导出后离线解析 SQL 计算期望摘要。无需长时锁，但解析器必须完整理解该版本所有转义、二进制、注释与例程语法；现有工具没有这种已验证解析器，不能用临时脚本凑出参照。

## 生产执行的详细门禁（本文件未执行）

1. 重新确认目标主机、端口、库名、版本、`server_id`、ledger、表引擎和候选hash。仅当目标33张业务表及所有参与对象均为InnoDB、无并发DDL时才采用该方案。准备新的受限ACL目录和全库空余空间，保留旧备份与失败日志。
2. 依窗口批准先阻断定时任务、API新增准入、主Worker、分析/翻译Worker、Discord和所有导入/手工写入者；核对进程、事务、租约、排队Run及数据库连接。锁不能替代排空；已有长事务可能使锁获取长时间等待。
3. 专用连接设置短`lock_wait_timeout`，获取`FLUSH TABLES WITH READ LOCK`；获取失败即停止，不杀未知连接。锁连接保持存活，明确记录连接ID、获取/释放时间，并独立监控其存活。锁释放、连接中断或数据库重启会使整个快照作废。
4. 逐表通过稳定主键升序流式读取所有原有列，计算精确行数和固定大小（建议10000行）分块SHA256。Canonicalizer必须明确NULL与空串、数值/字符串、二进制字节、DATETIME(3)及UTC时区、JSON原始字节、列序与字段长度；使用长度前缀防拼接歧义。每一块记录首/末主键的不可逆标识、行数和摘要；源端与恢复端使用同一版本脚本。原文只在受限进程内流转，不打印SQL、业务行、凭据或连接串。
5. 在锁保持期间，以独立`mysqldump --no-defaults --single-transaction --quick --routines --triggers --events --hex-blob --default-character-set=utf8mb4 --no-tablespaces`导出全库，记录工具版本、范围、退出码、stderr错误类别、dump字节数与SHA256。`mysqldump`独立连接无法继承锁连接的MVCC视图；本方案通过全局读锁保持同一数据库状态。任何服务启动、锁丢失、dump非零或磁盘告警立即判失败，先保存证据再释放锁。
6. dump后、解锁前，用同一专用连接再算逐表精确计数/分块摘要。前后不等即停；相等后释放锁并记录锁持有时长。核对结构定义/索引/FK/CHECK、ledger、触发器/例程/事件清单与定义摘要，避免只凭表数据放行。元数据对象在锁期间不得变更；若发生DDL或锁丢失，整次备份作废。
7. 在新的非3306/非43307隔离实例按已验证的显式客户端参数无`--force`导入，退出码和ERROR数必须为0。用同一Canonicalizer生成恢复端逐表计数/分块摘要，与锁下源端清单逐项比较；对象定义与数量也逐项一致。任一差异即NO-GO。报告保留dump及证据SHA、脚本SHA、身份、用时、空间变化、锁时间和脱敏差异定位，原始数据只留受控路径。

大表 `po_sync_run_contents` 恢复端已有精确3,969,055行。两次源端全表扫描、一次dump、一次恢复端扫描至少会读取/写入数GB数据，不能从三行夹具的耗时推断生产窗口。全局读锁会阻塞所有数据库写入，Discord及其他平台共用库也受影响；锁持续到第二次源端扫描结束，可能远长于此前13秒dump。应先在不持生产锁的只读限速扫描估算吞吐与IO、CPU和磁盘余量，再由项目经理选定停机窗口和最长锁时限；超时直接失败，不能临时延长。

`information_schema.table_rows`为估值，不能用于精确匹配。摘要是数据完整性证据，不等同恢复业务行为测试。敏感原文不能进入聊天、普通日志或临时仓库目录。若全局读锁不可接受、取得锁失败或数据/对象清单算法未独立复核，维持NO-GO并重新设计备份方式。
