# 同步进度与完成状态修复

## 问题与定位

欢乐战三国任务 `6c95fe87-aeb5-46f7-ad85-a74176cf0064` 已于 2026-10-12 17:52:09（北京时间）结束，实际关联 35 条帖子、155 条评论。结果为 `partial`：一个入口触及站点分页上限。35/35 是当时已发现的帖子数，并不是所有入口及评论任务的已知总量。

右下角 Dock 把页面平台筛选 `platform` 加入单任务 GET 请求，但任务接口不接受该参数，返回 400；原错误处理静默重试，状态始终停在提交时的“等待执行”。恢复终态任务时，仅传 id/status 会导致 Dock 停止轮询而保留零计数。

## 修改逻辑与文件

- `bigPlayer/admin/PublicOpinion/assets/sync-run-dock.js`：单任务查询只发送接口支持的范围参数，保留 region/community 等范围限制；状态刷新失败明确提示重试；显示帖子和实际评论数，避免把动态发现量当成待完成总量；提示文字进行 HTML 转义，部分完成提供简短详情入口说明。
- `assets/sources.js`：运行时展示不确定进度及已采集数量，等待和暂停独立显示，不再出现 35/35、99% 的伪总进度。真正收到任务终态后显示“爬取完成”“爬取结束（部分完成）”、失败或取消。读取接口真实评论正文数，扣除回复后展示顶层评论；实时进度返回的完整任务数据同步至 Dock，防止恢复终态任务数量归零。
- `assets/source-sync-progress.js`：将部分完成的诊断 JSON 转为可读原因，明确分页上限与已保存内容。
- `assets/scope.js`、`sources.html`：更新相关脚本缓存版本。
- 新增状态回归测试、Dock 参数与错误回归，以及可见浏览器验收脚本和结果。
