# 负面内容关注级与负面待处理算法重梳理

日期：2026-09-18

状态：用户已确认，待项目经理派单

## 1. 一句话需求

所有被判定为负面情感的帖子、动态、评论和回复，至少进入关注级；涉及游戏体验、游戏服务或运营问题的负面内容直接进入负面待处理，并优先进入当前告警处理链路。

## 2. 用户已确认的业务决策

1. 负面内容不能留在正常区，最低等级为关注级。
2. 游戏内容相关问题要第一时间得到处理。
3. 关注级与负面待处理互斥，同一条内容不能同时出现在两个页面。
4. 规则适用于国内、境外、所有社区类型、所有平台和所有内容类型。
5. 新分析、重新分析和历史数据回算使用同一套规则。

### 2.1 2026-09-21 补充口径与现场样本

用户再次确认风险分层的业务含义：

1. “负面待处理”不是只收录极端事故。只要内容为负面情感，且涉及游戏玩法、功能 Bug、奖励、数值、活动、登录、付费、网络、服务稳定性或直接影响游戏体验的问题，就必须归入 `urgent`。
2. “关注级”仅用于无关痛痒、可处理也可不处理的一般负面表达，例如轻微吐槽、主观偏好和没有明确游戏问题或实际影响的抱怨。
3. 正面内容不进入关注级或负面待处理；中性内容仍按既有明确风险证据规则判断。
4. 页面口径保持互斥：`urgent` 只进入“负面待处理”，`attention` 只进入“关注级”。

现场截图显示，近 7 天筛选下“负面待处理”为 1 条、“关注级”为 631 条，分布明显偏离上述业务定义。以下可见样本应作为回归用例：

| 外部内容 ID | 可见内容 | 当前结果 | 期望结果 | 归类原因 |
|---|---|---|---|---|
| `919167` | “今天早上云顶出 bug 了，导致我 9 点多才正常打上……” | 负面 80%，关注级 | 负面待处理 | 明确的游戏玩法 Bug，已经影响正常参与 |
| `919098` | “今天试炼之地有个红点消不掉，是怎么回事？” | 负面 68%，正常 | 负面待处理 | 明确的玩法界面/功能 Bug |

以上样本不能仅通过调高情感阈值修复；系统必须先识别“负面 + 游戏问题类型”，再执行风险等级归一化。

## 3. 当前问题

当前 AI 提示词明确要求“普通负向表达不得自动判为 attention”，而接口筛选又将：

- `severity=urgent` 映射为“负面待处理”；
- `severity=attention` 映射为“关注级”；
- `severity=normal` 排除在两个页面之外。

因此，`sentiment=negative` 但模型给出 `severity=normal` 的内容会直接消失在两个处理页面之外，造成负面待处理数量偏少。

## 4. 新的分层算法

算法分为“模型结果”和“系统兜底归一化”两步。系统归一化只能提升风险等级，不能把负面降级。

### 4.1 基础兜底

| 输入条件 | 最终等级 |
|---|---|
| `sentiment=negative` 且模型 `severity=urgent` | `urgent` |
| `sentiment=negative` 且模型 `severity=attention` | `attention` |
| `sentiment=negative` 且模型 `severity=normal` | 自动提升为 `attention` |
| `sentiment!=negative` | 保留现有 severity 规则 |

### 4.2 游戏问题类升级

负面内容命中以下任一类游戏问题信号时，最终等级提升为 `urgent`；不要求同时达到额外的负面分数阈值：

- 稳定性：闪退、崩溃、卡死、严重卡顿、无法启动；
- 登录与账号：无法登录、账号异常、封禁申诉、角色/存档丢失；
- 付费与资产：充值失败、重复扣费、退款、道具/货币丢失、奖励未到账；
- 服务与网络：服务器不可用、连接失败、匹配失败、长时间掉线；
- 版本与运营：更新后不可用、活动无法参与、活动奖励异常、版本兼容问题；
- 玩法与功能：玩法无法正常进行、功能异常、界面红点或状态无法消除、数值或规则异常，以及用户明确描述的游戏 Bug；
- 公平与安全：外挂、作弊、恶意利用漏洞、账号安全风险；
- 其他明确表达“无法使用、已造成损失、持续影响、要求尽快处理”的游戏问题。

命中方式可综合使用标题/正文/评论上下文、AI topics、系统问题词表和模型风险说明。运营关键词可以补充命中，但不能覆盖系统兜底规则。

### 4.3 非游戏问题的中度负面升级

非游戏问题类负面内容，满足“负面强度达到中高区间且模型置信度达到有效区间”时升级为 `urgent`；首版默认阈值由开发按现有字段实现为：

- `negative_score >= 0.60`；
- `confidence >= 0.60`。

阈值必须做成可调整常量或配置，测试报告中给出升级前后样本数量和误报抽样结果。若开发评估现有数据分布不适合该阈值，需在派单回执中提出替代值，不得静默修改业务口径。

### 4.4 最终等级取最高级

等级优先级固定为：`urgent > attention > normal`。最终等级为模型等级、负面兜底等级、游戏问题升级等级三者中的最高级。

## 5. 页面与告警口径

1. “关注级”页面：只查询最终 `severity=attention`。
2. “负面待处理”页面：只查询最终 `severity=urgent`。
3. 两个页面不得通过“sentiment=negative”再次扩大或交叉筛选，避免重复。
4. 概览负面内容卡片、负面数量、趋势与处置中的当前告警数量，统一读取归一化后的最终等级。
5. 游戏问题类负面升级为 `urgent` 后，进入当前告警处理链路：
   - 新内容不等待聚合窗口，按立即处理进入队列；
   - 同一内容重复分析、重复抓取必须幂等，不得重复生成告警；
   - 已解决、误报或已人工处理的历史告警状态不得被重复打开，除非产生新的内容版本或明确重新触发事件。

## 6. 历史数据处理

1. 对已有 `sentiment=negative` 的分析记录执行一次确定性回算：
   - `normal` 至少改为 `attention`；
   - 命中游戏问题信号或中度负面阈值的改为 `urgent`。
2. 回算优先使用现有 `sentiment / severity / negative_score / confidence / topics / title / body`，不重新调用 AI。
3. 回算后刷新内容列表、关注级数量、负面待处理数量和概览卡片。
4. 历史内容只补齐处理列表和告警数据，不追发历史钉钉/站内通知，避免一次性重复通知。
5. 无分析记录的内容不直接猜测为负面，继续由分析任务完成后进入本规则。

## 7. 数据与接口要求

- 最终等级必须持久化到现有 `po_analyses.severity`，不能只在前端临时计算。
- 保留模型原始等级和归一化原因，建议在 `analysis_reason` 或等价审计字段中记录：`negative_fallback`、`game_issue_upgrade`、`negative_score_upgrade` 等原因。
- 现有 `riskMode=negative` 继续映射 `severity=urgent`；`riskMode=attention` 继续映射 `severity=attention`。
- 统计接口、列表接口、概览接口和告警接口必须共享同一最终等级口径。

## 8. 异常与边界

- 模型返回 `sentiment=negative`、`severity` 缺失或非法：按负面最低关注级处理，并记录分析数据异常。
- 游戏问题词命中但 sentiment 不是 negative：不因关键词单独升级，避免正向攻略、公告或客服答复被误报。
- 同一内容同时命中多个游戏问题类别：仍只保留一个 `urgent`，原因记录可多值。
- 评论和回复使用自身正文与父帖上下文共同判断；不得只因父帖负面就强制子评论为负面。
- 删除内容、停用社区、无权限内容继续沿用现有可见性和过滤规则，不因风险升级改变权限。

## 9. 验收用例

| 前置条件 | 操作 | 预期结果 |
|---|---|---|
| 负面情感、severity=normal 的普通抱怨 | 打开关注级页面 | 出现于关注级，不出现在负面待处理 |
| 负面情感、正文含“更新后闪退” | 完成分析 | 进入负面待处理，并生成一条可幂等复用的当前告警 |
| 负面情感、正文含“充值扣费未到账” | 完成分析 | 进入负面待处理，优先级为 urgent |
| 负面情感、正文含“玩法出 bug 导致无法正常参与” | 完成分析 | 进入负面待处理，不受互动量和额外分数阈值限制 |
| 负面情感、正文含“玩法页面红点消不掉” | 完成分析 | 进入负面待处理，归一化原因为游戏功能问题 |
| 负面情感、非游戏一般不满、分数低于阈值 | 完成分析 | 进入关注级，不进入负面待处理 |
| 负面情感、negative_score 与 confidence 均达到阈值 | 完成分析 | 进入负面待处理 |
| 同一内容重复分析或重复抓取 | 重复触发分析 | 等级不降级，告警不重复创建 |
| 已有历史 negative + normal 数据 | 执行一次回算 | 至少进入关注级；命中游戏问题的升级为负面待处理 |
| 正向攻略含“闪退解决方法” | 完成分析 | 不因关键词单独升级 |
| 负面父帖下的中性评论 | 完成分析 | 按评论自身情感和上下文判断，不强制继承父帖等级 |
