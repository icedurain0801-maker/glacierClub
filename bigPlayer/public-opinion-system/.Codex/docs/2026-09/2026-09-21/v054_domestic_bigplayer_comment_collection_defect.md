# 国内 BigPlayer 社区评论抓取为 0

## 一句话需求

修复国内所有 BigPlayer 社区只能抓到帖子、抓不到评论及评论回复的问题；定时抓取和手动“开始同步”都必须真实抓取评论内容、正确入库并进入后续 AI 分析流程。

## 现场证据

- 页面范围：`境内 / 超能世界国服版 / BigPlayer社区 / 2026-09-21`。
- 页面统计：帖子 `96`，评论 `0`。
- 帖子 `920098` 的列表“评论数”为 `1`，说明平台帖子元数据已经声明存在评论，但系统没有对应的评论内容入库。
- 当前前端仍显示“该站点当前仅提供评论数量，评论内容接口暂不支持”，但后端 `bigPlayerH5Connector` 已存在 Q1 评论接口与分页实现，页面口径与系统能力不一致。

## 修复范围

1. 覆盖境内所有 `bigplayer_h5` 采集源，不得只修复“超能世界国服版”或单个采集源。
2. 同时覆盖定时调度、手动开始同步和失败重试链路。
3. 帖子、动态只要平台声明评论数大于 0，或已存在评论检查点需要续跑，都必须进入评论采集任务。
4. 抓取顶层评论及评论内回复，保存正确的根帖、父评论、层级和平台评论 ID。
5. 新增或变化的评论、回复入库后，按普通抓取内容进入 AI 分析、风险分级和告警流程。

## 缺口补抓

- 修复上线后，对境内 BigPlayer 内容执行一次确定性缺口扫描：平台声明评论总数大于当前已入库有效评论数的帖子，重新进入评论采集队列。
- 补抓以“声明数与已入库数存在缺口”为准，不硬编码单一社区或单一日期。
- 已存在评论必须幂等更新，不得重复创建；平台已删除或隐藏的评论按现有删除状态规则处理。
- 补抓历史评论不追发历史外部通知，但需要完成分析并在页面统计中可见。

## 失败与状态口径

- 不得用帖子元数据中的评论数量冒充已抓取评论内容数量。
- 评论接口授权失败、分页失败、响应结构异常、父子关系无法解析时，抓取任务必须标记为 `partial` 或 `failed`，记录明确错误码；不得以“成功、评论 0 条”静默结束。
- 如果平台确实返回空评论列表但声明评论数大于 0，记录“声明数与实际返回不一致”的可诊断状态并进入可重试队列。
- 评论抓取恢复后，删除前端“评论内容接口暂不支持”的旧提示，改为展示真实评论与回复进度；仅在能力检测明确不支持时显示不支持。

## 验收标准

| 场景 | 预期结果 |
|---|---|
| 帖子 `920098` 平台仍返回 1 条评论 | 评论内容真实入库，页面评论统计至少增加 1，详情可见评论正文 |
| 新帖子声明评论数大于 0 | 同一轮或后续可追踪任务自动抓取评论，不停留在帖子计数 |
| 评论包含回复 | 顶层评论和回复均入库，根帖及父评论关联正确 |
| 定时 6 小时抓取 | 帖子、评论、回复均进入同一次可审计运行，不再长期为 0 |
| 手动“开始同步” | 创建真实 Worker 任务并产生评论抓取进度与新增数据 |
| 评论接口异常 | 任务显示部分完成或失败及明确原因，不显示成功 0 条 |
| 重复执行同一批次 | 评论不重复，检查点可续跑，统计不虚增 |
| 国内其他 BigPlayer 社区 | 使用同一修复逻辑，不依赖特定社区名称或站点地址 |
