# BigPlayer 旧采集器下线需求

## 1. 一句话需求

彻底下线当前 BigPlayer 采集器的运行实现，保留舆情后台页面、配置、数据库结构和历史数据，待后续需求重新设计并实现新的 BigPlayer 采集器。

## 2. 已拍板决策

- 删除/下线 BigPlayer 连接器运行实现、定时调度注册、worker 执行接线和手动同步运行接线。
- 保留后台页面，不删除抓取账号管理、抓取任务记录、抓取内容管理等页面及导航。
- 保留 BigPlayer 采集源、账号、站点地址、授权状态、采集频率等历史配置。
- 保留数据库表结构、历史 Run、历史帖子/动态/评论、分析和翻译结果。
- Discord、TapTap、Facebook、X、Lounge 等非 BigPlayer 平台不在本次删除范围。
- 不设计新采集器，不迁移或清洗历史数据；新实现另行立项。

## 3. 现状与问题背景

当前 BigPlayer 运行链包含连接器、源级同步 API、常驻 worker、统一调度器、站点/账号授权绑定及多站点运行逻辑。近期已经出现定时窗口、worker 准入和多站点身份等问题；继续保留旧链路会让后续重写继续误接旧逻辑，也可能产生假成功、假进度或新的历史数据污染。

本需求只负责“旧实现下线”，不把既有问题修复混入本阶段。历史缺陷文档仅作为范围依据：

- `.Codex/docs/2026-09/2026-09-23/v001_scheduler_timezone_window_regression.md`
- `.Codex/docs/2026-09/2026-09-22/v002_bigplayer_0922_window_exclusion.md`
- `.Codex/docs/2026-09/2026-09-22/v356_bigplayer_runtime_reactivation_plan.md`

## 4. 保留范围

### 4.1 页面与导航

- 舆情分析系统侧边栏和六个后台页面保留。
- 抓取账号管理中的 BigPlayer 社区入口、列表、详情、编辑表单和已保存字段保留。
- 抓取任务记录中历史 BigPlayer Run 可查询、可查看详情；不再产生新的 BigPlayer Run。
- 抓取内容管理中的历史 BigPlayer 帖子、动态、评论及其分析/翻译结果保留。

### 4.2 配置与数据

- `po_sources`、`po_accounts` 及相关通用表结构保留，不执行删除表或清空数据。
- BigPlayer 采集源的站点地址、多站点配置、采集频率、授权摘要和启停状态保留。
- 历史 `po_sync_runs`、checkpoint、历史内容和关联分析/翻译任务保留，作为后续重写的只读参考。
- 不回写、不重算、不批量修改历史数据。

## 5. 下线范围

### 5.1 服务端与连接器

- 下线 `server/src/connectors/bigPlayerH5Connector.js` 的生产运行入口及其注册接线；不得再由 API 或 worker 调用 BigPlayer 抓取。
- 下线 BigPlayer 专用的授权刷新、能力检测、站点探测、登录会话续期等运行接线；不得继续产生真实网络请求。
- 通用 connector 注册表、其他平台 connector 保留且行为不变。

### 5.2 API 与 worker

- `POST /sources/:id/sync`、`POST /sources/:id/collect`、`POST /sources/:id/sync/resume` 等涉及 BigPlayer 的运行入口统一 fail-closed：返回明确的 `BIGPLAYER_COLLECTOR_DECOMMISSIONED`（或项目既有等价错误码），HTTP 状态按现有业务错误规范处理。
- BigPlayer 请求不得创建新的 `po_sync_runs`、checkpoint、lease 或 worker 队列消息。
- 常驻 worker 和统一调度器继续运行其他平台，但必须跳过 BigPlayer；不能因为 BigPlayer 被跳过而阻塞或改变其他来源的调度。
- 不返回“已开始”“授权成功”“同步完成”等假成功，不播放假进度，不写入新的成功/失败运行记录。

### 5.3 页面临时状态

- BigPlayer 的“开始同步”“恢复同步”“能力检测/授权检测”等会触发运行链的按钮置灰或拦截。
- 页面显示统一文案：`BigPlayer 采集功能重构中，暂不可同步`。
- 若保留按钮形态，点击后只展示该文案和错误码，不发起 API 请求；不得伪造进度。
- BigPlayer 配置字段仍可查看。是否允许编辑配置按现有页面能力保留，但保存不能触发采集；若实现无法保证保存安全，改为只读并显示“运行能力重构中”。
- 历史任务详情中的状态和结果照常展示，不将历史记录改写为“已删除”。

## 6. 接口契约

| 场景 | 预期行为 |
|---|---|
| 查询 BigPlayer 来源/账号 | 正常返回脱敏配置和历史状态，不返回密钥明文 |
| 打开 BigPlayer 配置页 | 页面可打开，历史字段可展示；显示“功能重构中”提示 |
| 点击开始同步/恢复同步 | 前端拦截或后端返回 `BIGPLAYER_COLLECTOR_DECOMMISSIONED`；不得入队 |
| 点击能力/授权检测 | 不调用旧探测链；返回“采集功能重构中”，不得伪造检测成功 |
| 调度器扫描 BigPlayer | 明确跳过并记录可观测原因；不创建 Run，不占用租约 |
| 调度器扫描其他平台 | 继续按既有逻辑执行，结果不受影响 |
| 查询历史任务与内容 | 只读正常，历史数据不丢失 |

## 7. 数据与安全边界

- 本阶段禁止删除 `po_sources`、`po_accounts`、`po_sync_runs`、`po_contents` 及分析/翻译相关历史数据。
- 本阶段禁止删除或轮换已有授权密文；不得在日志、错误响应或页面中暴露 token、密码、cookie、session。
- 本阶段禁止修改通用调度器的时区、租约、窗口算法；这些属于独立缺陷，不随下线变更扩散。
- BigPlayer 被跳过的原因应可审计，但日志只记录 source id、platform、错误码和时间，不记录凭据。

## 8. 验收标准

1. BigPlayer 后台入口、列表、表单和历史任务详情可正常打开，历史数据数量与下线前一致。
2. 任意 BigPlayer 来源点击“开始同步/恢复同步/能力检测”后，不产生网络抓取、不创建 Run、不写 checkpoint、不进入 worker 队列，并显示统一“功能重构中”提示。
3. 重启 worker 或调度器后，仍不会自动创建 BigPlayer 任务；其他平台仍能正常被扫描和执行。
4. 对一个已授权 BigPlayer source 做只读检查，授权摘要、站点地址、频率和历史内容均可查询，敏感字段不泄露。
5. 对一个 Discord/TapTap/Facebook source 做回归，手动同步、定时调度和历史查询行为与本次变更前一致。
6. API、worker、页面均没有假成功或假进度；错误码和文案可被前端稳定识别。
7. 开发负责人提交下线文件清单、旧入口搜索结果、单元/集成测试结果和回滚说明；未得到新的重写需求前，不恢复 BigPlayer 运行能力。

## 9. 不在范围

- 不重写新的 BigPlayer 采集器。
- 不修复 BigPlayer 的抓取窗口、评论抓取、多站点、token 自动续期等旧问题。
- 不删除历史配置、历史内容、历史任务或数据库表。
- 不改负面/关注级算法、翻译、钉钉通知、概览页面、侧边栏和其他平台采集逻辑。
- 不执行 push、合并、tag、发版或生产数据删除；这些操作需各自会话另行弹窗确认。

已拍板决策：用户确认采用“彻底下线并删除现有 BigPlayer 采集实现，保留后台页面、配置、表结构和历史数据”。
