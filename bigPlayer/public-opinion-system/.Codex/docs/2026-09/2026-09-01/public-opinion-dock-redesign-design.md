# 公共意见 Dock 重设计方案

- **文档日期**：2026-09-01
- **适用范围**：`bigPlayer` 仓库中的公共意见管理模块
- **设计状态**：已确认，可进入渐进式实施
- **方案基线**：仅公共意见模块、渐进式重构、Dock 轻量后台
- **参考资料**：`E:\chrome下载\DESIGN.md`

## 1. 目标与范围

### 1.1 目标

将现有公共意见管理端从传统后台视觉升级为 Dock 风格的轻量工作台，同时保持现有数据能力、业务语义和接口契约稳定。重设计优先解决信息层级、页面一致性、筛选与处置效率，以及桌面端和窄屏端的可用性问题。

### 1.2 本次包含

- 公共意见模块的共享 Dock 壳层：导航、顶部工作区、页面标题区、作用域选择器、反馈与错误呈现。
- 6 个现有页面的视觉和布局迁移：
  1. 舆情数据概览（`index.html`）
  2. 舆情通知管理（`alerts.html`）
  3. 抓取内容管理（`content.html`）
  4. 监控关键词设置（`keywords.html`）
  5. 抓取账号管理（`sources.html`）
  6. 抓取任务记录（`collection-runs.html`）
- 现有详情抽屉、筛选、分页、状态处置、采集触发、来源授权和进度状态在新壳层中的承载方式。
- 页面级灰度、旧页面回退和 API 兼容策略。

### 1.3 本次不包含

- 其他后台模块的视觉改造或导航重构。
- 公共意见后端数据模型、采集器、AI 分析器、通知器和鉴权协议的重写。
- 新增业务指标、告警规则、采集平台或权限角色。
- 将静态原型一次性迁移至新框架；技术实现以渐进式抽取和复用现有脚本为准。
- 移动端独立 App 或离线能力。

## 2. 设计原则

1. **Dock 是壳层，不是新业务系统**：先统一导航、排版、表面和交互反馈，再逐页替换内部视图。
2. **渐进式重构**：每页可独立上线、验证和回退；旧 URL、查询参数和 API 路径继续有效。
3. **轻量后台**：使用暖米白画布、细边框、低阴影和明确的钴蓝操作色；页面服务于扫描、比较和重复处置，不使用营销式大幅 Hero。
4. **信息优先**：关键数值、风险等级、时间、范围和状态必须在首屏可扫描；装饰不能与业务内容竞争。
5. **安全默认**：前端不接触明文凭据，不绕过现有鉴权和服务端权限，不把来源原始内容当作可信 HTML。

## 3. 视觉 Tokens

Tokens 来源于 `DESIGN.md`，并针对轻量后台做语义映射。实现时优先使用 CSS 自定义属性，避免页面各自定义同义颜色。

### 3.1 颜色与表面

| Token | 值 | 用途 |
|---|---|---|
| `--color-canvas-cream` | `#faf9f7` | 页面主画布，禁止用纯白替代 |
| `--color-surface-ivory` | `#fbfaf7` | 卡片、筛选区、次级面板 |
| `--color-pure-white` | `#ffffff` | 顶部导航、输入框、提升一级的抽屉和弹层 |
| `--color-lavender-mist` | `#f4f0ff` | 少量分析高亮或空状态背景 |
| `--color-powder-blue` | `#d6e4f1` | 中性控件边框和蓝色分隔线 |
| `--color-ink-charcoal` | `#121722` | 标题、正文、主要图标 |
| `--color-slate-gray` | `#777c86` | 次要文字、表头、元数据 |
| `--color-steel-gray` | `#a5a5a5` | 占位、禁用、辅助说明 |
| `--color-hairline` | `#efefef` | 1px 边框和分割线 |
| `--color-faint-gray` | `#cccccc` | 非重点图标描边 |
| `--color-electric-cobalt` | `#0068f9` | 主操作、链接、当前项、进度 |
| `--color-deep-cobalt` | `#024bb1` | hover、pressed |
| `--color-cerulean` | `#0074dd` | 低频辅助蓝色信息 |
| `--color-vivid-violet` | `#6736eb` | 装饰、高亮标签、少量指标，不用于主 CTA |
| `--color-forest` | `#046645` | 成功和完成态的辅助色 |

业务状态色允许建立语义别名，但不改变基础色原则：紧急/负面使用红色系，关注使用橙色系，成功使用 Forest，待处理使用 Cobalt；状态色只用于状态本身，不铺满页面。

### 3.2 字体与排版

- `--font-dock`: `'Roobert', Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', 'Microsoft YaHei', sans-serif`。
- 中文环境优先保证清晰度；Roobert 不可用时使用 Inter 或系统无衬线字体。
- 后台页面不使用 84px 营销 Hero 字号。页面标题使用 32px/1.2，区块标题 20px/1.38，正文 14px/1.55，元数据 12px/1.5；总览关键指标可使用 32px。
- 字重使用 400、500、600、700。交互密集区域不使用过窄字距；字母间距默认 `0`，仅英文小型标签可使用轻微 tracking。

### 3.3 间距、圆角与阴影

- 基础单位：8px；常用间距 8、16、24、32、40、48、64。
- 页面内容最大宽度：1200px；桌面内边距 32px，窄屏内边距 16px。
- 卡片圆角 16px；图片 16px；按钮、标签和选中导航项 48px 胶囊；小型状态标签可使用 8px。
- 边框统一 1px `--color-hairline`，必要时使用 `--color-powder-blue`；禁止厚重描边。
- 卡片优先靠表面明度和边框分层；使用微弱 `--shadow-subtle`，详情图或关键浮层使用 `--shadow-lg`，禁止重阴影、发光和彩色阴影。

## 4. 页面骨架

### 4.1 共享 Dock 壳层

```text
<body>
  <aside class="dock-sidebar">
    品牌 / 公共意见模块导航 / 当前项 / 环境与用户入口
  </aside>
  <main class="dock-main">
    <header class="dock-topbar">
      面包屑或模块名 / 全局范围选择 / 刷新与主要操作
    </header>
    <section class="dock-page-header">
      页面标题 / 一句话上下文 / 页面级操作
    </section>
    <section class="dock-page-content">
      筛选、指标、表格、图表、详情等业务内容
    </section>
  </main>
</body>
```

桌面端保留固定宽度侧栏和可伸缩内容区；侧栏只承载模块导航，不在每页复制业务菜单。顶部范围选择器统一维护区域、游戏、社区、平台和时间范围上下文，并通过现有查询参数传递给各页。

### 4.2 共享组件契约

- `DockShell`：负责页面容器、当前导航项、页面标题和全局反馈挂载点。
- `ScopeBar`：展示并维护范围上下文；选择变更后触发当前页重新加载，不改变业务 API 响应结构。
- `PageHeader`：标题、说明和页面操作；操作按钮必须有明确 loading/disabled 状态。
- `MetricStrip`：总览指标；指标点击只导航到已有页面和筛选范围。
- `FilterBar`：文本、选择、日期和状态筛选；支持清空、回车提交和 URL 同步。
- `DataTable`：表头、排序/分页、空态、加载态、错误态和窄屏横向滚动。
- `StatusBadge`：统一显示告警、采集源、任务和分析状态。
- `DetailDrawer`：内容或告警详情；支持关闭、Esc、遮罩点击和加载失败回退。
- `Toast/InlineState`：操作成功、失败、超时、无权限和空数据反馈。

## 5. 六页迁移策略

所有页面按“壳层接入 → 样式迁移 → 状态统一 → 回归验证 → 灰度切换”执行。页面内部业务脚本可先保留，通过适配器挂入 Dock 容器；完成验证后再拆除旧样式和重复 DOM。

### 5.1 总览页

- 保留现有 `/overview`、`/sources`、趋势、议题、告警和负面热帖数据能力。
- 首屏结构改为：页面标题与范围条 → 指标带 → 分析/数据状态条 → 两列分析区 → 告警与负面热帖工作区。
- 指标、趋势和议题使用白色/象牙色轻表面；钴蓝表示正向交互和趋势主线，红/橙仅表达风险。
- 保留真实模块完成度驱动的加载进度、30 秒超时、局部错误和空数据说明；禁止用时间动画伪造进度。
- 先迁移壳层和状态组件，再迁移图表与卡片，最后移除旧的蓝灰渐变 command bar。
- 回退点：通过页面开关回到当前 `index.html`，不改变 URL 和接口。

### 5.2 告警页

- 保留告警列表筛选、分页、状态处置、解决备注、详情抽屉和通知状态。
- 列表首要列为严重级别、标题/触发摘要、范围、发生时间、当前状态和处置入口；使用状态徽标而非整行强色。
- 详情抽屉采用白色提升表面，分为告警摘要、触发内容、关联内容、AI 分析、通知记录和处置操作。
- 保存处置时沿用 PATCH 契约；按钮提交中锁定，成功后刷新当前结果并给出 toast，失败保留用户输入。
- 告警详情的原文和触发点按纯文本安全渲染，外链使用 `target="_blank"` 与 `rel="noreferrer noopener"`。

### 5.3 内容页

- 保留内容筛选、内容类型、情感、平台、日期、关键词、分页、内容详情和媒体展示。
- 桌面端采用高密度但有呼吸感的表格；标题、摘要、来源、情感和发布时间形成可扫描行。
- 详情抽屉展示原文、媒体、作者/来源、情感和负面强度、话题、命中关键词、摘要及来源链接。
- 图片加载失败显示轻量占位，不阻塞正文；富文本、外部内容和 URL 必须经过现有转义/安全策略。
- 迁移顺序为筛选条和表格壳层 → 行状态和分页 → 详情抽屉 → 媒体与空态。

### 5.4 关键词页

- 保留关键词的增删改、启用/停用、范围绑定和匹配规则语义。
- 页面结构为标题与新增操作 → 作用域/状态筛选 → 关键词列表 → 编辑抽屉或表单。
- 编辑表单显式区分关键词文本、匹配方式、所属区域/游戏/社区、启用状态和备注；危险操作需要确认。
- 保存失败时保留表单值并显示字段级或行级错误；冲突和重复由服务端判定，前端不作最终授权判断。

### 5.5 来源页

- 保留来源列表、启停、平台/区域/游戏/社区范围、登录挑战、凭据授权检查和立即采集入口。
- 来源行展示平台、账号/来源名、范围、启用状态、授权状态、最近同步和操作菜单。
- 凭据输入使用密码控件和最小暴露原则；页面不回显服务端密文或完整 token。
- `manual_verification`、验证码、扫码、设备确认等状态使用明显但克制的状态条，并提供跳转到现有深链接。
- “立即采集”仅在具体且已启用社区可执行；停用社区只能查看历史数据。所有条件仍由服务端再次校验。

### 5.6 采集任务记录页

- 保留运行列表、时间范围、平台/来源/状态筛选、分页、运行详情、失败原因和手动触发关联。
- 任务状态使用统一徽标和进度表达：排队、运行中、成功、部分成功、失败、可重试、已取消。
- 详情优先展示开始/结束时间、范围、抓取/分析数量、错误摘要、重试信息和关联来源；长错误支持复制但不暴露凭据。
- 任务轮询必须可停止、可超时、可处理过期响应；页面离开或切换范围时取消旧请求或忽略旧结果。

## 6. API 兼容与数据边界

### 6.1 兼容原则

- API 基地址继续由 `window.PUBLIC_OPINION_API` 覆盖，默认地址保持现有值。
- 保持现有资源和方法：`/games`、`/sources`、`/overview`、`/contents`、`/alerts`，以及现有详情、分析进度和采集运行相关路径。
- 保持现有查询参数名称和含义，包括 `period`、区域/游戏/社区/平台作用域、内容筛选和分页参数；新增参数必须向后兼容并可忽略。
- 保持成功响应 `data` 包装和错误响应中的 `error.message`/`message` 读取方式。Dock 只改变展示和请求编排，不重命名领域字段。
- 对字段别名在单一适配层归一化，例如 `created_at/createdAt`、`published_at/publishedAt`、`source_id/sourceId`；页面组件只消费归一化模型。
- API 版本或响应结构发生变化时，先在适配层兼容，不在六页中分别编写分叉逻辑。

### 6.2 请求生命周期

每次页面加载生成 request serial 或 AbortController。只允许当前作用域和当前请求更新 UI；旧请求晚到时丢弃。30 秒超时进入可重试错误态，局部模块失败不应清空其他已成功模块。

### 6.3 数据展示边界

服务端返回的标题、正文、作者、关键词、触发点、错误信息和 URL 默认不可信。渲染前进行 HTML 转义或使用安全的纯文本节点；只允许明确的 `http/https` 外链协议。前端不得拼接未经编码的路径参数、查询参数或 DOM HTML。

## 7. 安全边界

- 认证、会话续期、权限和社区范围校验仍由现有服务端负责；前端隐藏按钮不等于授权。
- 凭据只能通过既有安全接口提交，禁止写入 localStorage、URL、日志、DOM 文本或错误 toast；响应不得回显密文。
- 生产环境禁止把内部服务 token 注入浏览器；`LOGIN_SESSION_INTERNAL_TOKEN` 等仅允许服务端使用。
- 所有变更型请求使用既有 CSRF、会话和来源校验机制；Dock 不新增绕过路径。
- 内容详情和告警详情中的图片、链接、富文本按不可信外部内容处理，设置 `rel="noreferrer noopener"`，必要时采用 CSP 和安全图片代理。
- 采集触发、告警处置、关键词修改、来源启停等操作应记录操作者、时间、范围、结果和失败原因；日志不得含凭据和完整原文中的敏感信息。
- 越权、停用社区、缺少具体作用域和手动验证未完成时，前端给出可理解提示，服务端必须返回统一无权限/非法状态错误。

## 8. 响应式策略

### 8.1 断点

- `>= 1200px`：侧栏固定，内容区最大 1200px；总览使用双列分析布局，表格展示完整字段。
- `768px - 1199px`：侧栏收窄或折叠，内容区单列；总览分析模块纵向排列；表格保留横向滚动。
- `< 768px`：侧栏变为抽屉或顶部入口；范围选择器和操作区允许换行；指标两列或单列；详情抽屉占满宽度。
- `< 480px`：页面内边距 16px，按钮保持至少 44px 触控高度；复杂筛选折叠为筛选面板；表格可切换为关键字段列表，但不能丢失详情入口。

### 8.2 交互约束

- 所有可点击控件最小触控目标 44px。
- 文本、标签、按钮必须在其容器内换行或截断，不允许覆盖相邻内容。
- 图表设定稳定高度和最小柱宽；窄屏允许减少标签密度，但不得改变数据含义。
- 键盘可访问：侧栏、筛选、表格行操作、抽屉关闭和状态表单均有可见焦点；抽屉打开时焦点进入抽屉并在关闭后回到触发控件。
- 不依赖 hover 才能完成关键操作；移动端使用点击菜单和明确状态。

## 9. 状态模型

每个页面和共享模块至少覆盖以下状态：

| 状态 | 行为 |
|---|---|
| 初始 | 页面骨架和标题先出现，避免空白闪烁 |
| 加载中 | 关键区域显示稳定占位或文字状态；操作按钮按请求锁定 |
| 成功有数据 | 展示归一化后的数据、时间范围和来源上下文 |
| 成功无数据 | 说明当前范围没有数据，并提供清空筛选/切换范围入口 |
| 局部失败 | 仅失败模块显示错误和重试，保留其他模块 |
| 整页失败 | 显示错误摘要、重试按钮和必要的服务状态信息 |
| 超时 | 明确显示超时，不伪造完成度；允许重新加载 |
| 权限不足 | 不展示敏感数据，说明权限或范围限制 |
| 提交中 | 防止重复提交，保留当前表单和上下文 |
| 提交成功 | toast/行状态更新，必要时刷新数据 |
| 提交失败 | 保留用户输入，显示可操作错误 |
| 过期响应 | 丢弃旧请求结果，不覆盖新范围或新页面状态 |

特殊状态包括：来源 `manual_verification`、任务可重试、告警处理中/已解决、社区停用、Last Night 无社区。这些状态必须有明确文案和不误导的下一步。

## 10. 测试策略

### 10.1 单元与契约测试

- 测试 API 适配器的字段别名、空值、分页、错误包装和旧响应兼容。
- 测试作用域与时间参数的 URL 同步、编码和切换后请求隔离。
- 测试状态徽标映射、严重级别、情感、采集运行状态和手动验证状态。
- 测试安全渲染：HTML 注入、危险协议、属性转义、外链 rel 属性和凭据不落盘。
- 测试请求超时、局部失败、旧请求晚到和轮询停止逻辑。

### 10.2 页面集成测试

六页分别验证：首次加载、刷新、空数据、接口错误、筛选提交、分页、详情抽屉、键盘关闭、变更型操作成功/失败和返回列表后的上下文保持。告警处置、来源启停/采集、关键词修改等操作需验证服务端拒绝时的前端表现。

### 10.3 视觉与可访问性测试

- 在 1440、1024、768、390、375px 宽度下截图比对。
- 验证暖米白画布、钴蓝交互色、1px 边框、16px 卡片圆角、轻阴影和无溢出。
- 检查标题、表格、筛选器、抽屉和 toast 不重叠；中文长文本、长 URL、错误信息和无图片状态正常换行。
- 使用键盘完成导航、筛选、打开/关闭抽屉和提交表单；检查焦点顺序和 aria 标签。
- 检查主要文本与背景的对比度，风险颜色不作为唯一信息通道。

### 10.4 回归与灰度

每页迁移后运行现有服务端和前端相关测试，并在同一作用域下对比 Dock 页面与旧页面的关键数据、请求参数和操作结果。灰度开关按页面维度控制，保留至少一个版本周期的旧实现和回退入口。

## 11. 验收标准

### 功能

- 6 个页面均可从公共意见导航进入，当前项和页面标题正确。
- 现有 URL、作用域、时间范围、筛选、分页、详情和变更操作保持可用。
- 总览指标、趋势、议题、来源、告警和热帖数据与旧页面在相同请求条件下语义一致。
- 告警处置、来源状态、立即采集、关键词修改和任务查看均有成功、失败、权限不足和重复提交处理。
- 所有加载、空数据、局部错误、整页错误和超时状态可见且可恢复。

### 视觉

- 页面背景使用 `#faf9f7`；主操作使用 `#0068f9`，hover/pressed 使用 `#024bb1`。
- 页面没有厚重阴影、超过 1px 的常规边框、持续性大面积渐变或重复的营销式 Hero。
- 卡片、图片、按钮和导航项遵循约定圆角；排版层级和间距统一。
- Dock 壳层在六页一致，业务内容仍保持表格、指标、图表和处置工作流的后台密度。

### 安全与兼容

- 凭据、内部 token 和敏感响应不出现在 URL、localStorage、DOM 文本、客户端日志或 toast。
- 不可信内容不会执行 HTML/脚本；外链协议和 rel 属性符合安全约束。
- 服务端权限仍是最终判定，前端不存在仅靠隐藏控件实现的安全控制。
- 旧 API 响应、字段别名和错误包装通过适配层继续支持。

### 响应式与可访问性

- 375px 宽度下无水平页面溢出，复杂表格可在容器内滚动或降级为关键字段列表。
- 关键控件触控高度不低于 44px；键盘可完成主要流程；抽屉焦点管理正确。
- 关键文本不重叠、不被截断到无法理解；空态和错误态在桌面与移动端均可操作。

## 12. 实施顺序与回退

1. 抽取共享 Dock tokens、壳层、ScopeBar、状态组件和 API 适配边界。
2. 迁移总览页，验证视觉基线、状态模型和作用域同步。
3. 迁移告警页与内容页，验证详情抽屉和不可信内容渲染。
4. 迁移来源页与采集任务记录页，验证授权、手动验证、轮询和变更操作。
5. 迁移关键词页，完成表单、权限和审计行为收口。
6. 六页回归、响应式检查和灰度验收后，再清理旧页面重复样式。

每一步都保留旧页面入口和页面级开关。发生数据不一致、权限回归、严重布局问题或关键操作失败时，只回退对应页面，不回滚其他已验收页面；API 和服务端不因视觉迁移改变。
