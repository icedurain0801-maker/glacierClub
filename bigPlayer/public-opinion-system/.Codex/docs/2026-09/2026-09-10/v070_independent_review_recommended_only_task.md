# v070 独立审核仅展示系统推荐项任务单

## 已拍板范围

- 风险告警管理、优质内容管理的独立审核列表与详情抽屉，仅展示服务端 `recommend_home`、`recommend_pin`、`recommend_feature` 为严格布尔 `true` 的类型。
- 固定顺序：首页推荐、栏目置顶、加精；三项均未推荐时显示 `--`。
- 删除 `AI 建议` / `AI 不建议` 后缀；未推荐项的名称、状态及操作均不渲染。
- 可见审核项保持既有采纳、忽略、撤销语义；每项操作互不影响。
- 不改 AI 推荐算法、推荐字段、历史审核记录或服务端权限含义。

## 验收门禁

1. 只推荐加精时，列表和详情仅显示加精；不得出现首页推荐、栏目置顶或其操作。
2. 多项推荐只显示推荐为 `true` 的类型，顺序固定；三项均未推荐显示 `--`。
3. 风险告警与优质内容的列表、详情规则一致；已隐藏类型的历史审核记录不删除。
4. 无权限仅展示可见类型与状态；可见项操作互不影响；接口或字段异常不得回退为三项全部展示。
5. 不得修改推荐算法、历史审核数据或无关模块。

## 实现前置缺口（2026-09-10）

开发负责人三路只读审查一致确认，当前 API 合同不足以完整交付已确认的 PRD：

1. 风险告警的列表/详情没有独立审核 UI、推荐字段或审核操作；`GET /alerts` 仅返回告警数据，未关联 `po_quality_candidates`。实现两模块一致性需要最小 API/Repository 关联视图。
2. 优质内容的推荐字段来自 MySQL `TINYINT`，当前为 `0/1`；若前端以 PRD 规定的严格 `=== true` 判断，推荐值 `1` 会被隐藏。需 API 层归一化为 boolean，或更改 PRD 的严格 boolean 口径。
3. 当前前端/API 不提供 `canReview` 等权限合同；仅有 `x-admin-user` 审核人记录，无法可靠实现“无权限仅展示、不显示按钮”。

### 已拍板决策

用户已选择推荐方案：授权最小 API 扩展，完整交付风险告警、优质内容、详情与无权限态。

- API 将推荐字段归一化为 JSON boolean。
- 风险告警 API 返回关联质量候选的独立审核只读视图；无关联候选时返回空推荐项。
- API 提供只读 `canReview` 合同，前端据此隐藏操作按钮。
- 不修改 AI 推荐算法、推荐结果、历史审核数据、审核操作语义或现有权限判定逻辑。
