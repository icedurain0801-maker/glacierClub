# 舆情风险等级判定规则

Status: superseded
Updated: 2026-10-12
Policy: game-impact-evidence-v7

本文件保留 v7 历史设计。2026-10-12 后续用户批准的 v8 串行决策树见 [feature-risk-serial-gates.md](feature-risk-serial-gates.md)，负面分数不再单独升级，且按新低置信与紧急复核规则执行。

## 等级定义

| 等级 | 判定条件 | 例子 |
|---|---|---|
| normal 正常 | 正面分享、攻略或无关中性内容 | 分享已经修复闪退的方法；回复“收到，谢谢” |
| attention 关注级 | 一般负面不满，或与游戏体验相关的中性咨询；没有明确具体问题，且负面强度不大于0.50 | “请问崩溃反馈入口在哪？”；“感觉一般” |
| negative 紧急告警（合并展示） | 已进入关注候选且负面强度严格大于0.50，或本条原文报告实际故障/投诉/损失 | 反复崩溃、重连耗时、战斗不同步、奖励异常、匹配不公平反馈 |
| urgent 紧急级 | 先满足负面候选条件，AI原始判定严重，且本条原文中有可验证的严重影响证据 | 持续无法登录或游玩、全服中断、重大资产/进度损失、账号被盗或安全泄露 |

等级互斥，每条只保存最高等级；互动数、父帖等级、语气激烈、一个故障词、普通投诉、分数高或置信度高均不能单独升级紧急。正面内容保持normal；未知情感不凭空判定风险。

## 基准与边界

Laura 在 Last Light / Discord 报告发起联盟boss集结时约每十次崩溃一次，重连浪费时间并与队友不同步，最后询问是不是手机问题。原文已有发生的故障和体验影响，问句结尾不能覆盖前面的事实：判 negative，不因低负面分数、低置信度、AI漏标投诉而落回 attention。没有持续阻断、大范围影响或重大损失证据时，不应判 urgent。

恰好0.50不因分数升级，但实际问题依然进入negative。反问、平静表达和英文投诉与中文同一口径。假设、否定、已修复、解决方法/教程不作为发生中的严重事故证据；“修复后仍然发生”须按仍存在的问题判断。明确严重影响即使漏标gc，也至少进入negative。

## AI字段与后端校验

保留gx（游戏体验相关）、gc（具体投诉）及ge（投诉原文摘录）。新增ui（严重影响类别）：none / service_blocked / widespread_outage / asset_loss / account_security；ue为严重影响原文摘录，none时为空。

轻量/深度使用同一提示词规则，PROMPT_SCHEMA_VERSION=sentiment-quality-game-impact-evidence-v7；历史analysisVersion保持，不更改部署凭据或模型。新的缓存键包含新提示词版本，避免新任务复用旧提示词结果。

后端核对ue是否在本条原文中，并核对对应类别的严重影响表达。当前确定性表达支持中文和英文；不能验证的类别、捏造/父帖/摘要证据或缺少严重影响时保守降至negative或attention。旧结果缺少ui/ue时仅允许从本条原文识别明确严重影响。AI原始决定及经验证的源句随rawAnalysis进入risk_context；缓存和重复归一化可复核，显式提供的新正文优先，内容指纹变化按既有落库保护拒绝。

算法、AI解析、Worker、数据库落库/缓存、告警入口统一使用归一化规则。关键词命中可请求分析，不能绕过风险等级直接产生紧急告警。既有risk_context列与四档severity数据库约束为基础配置；正式库已具备，无本次迁移执行。

## 生效范围

新分析和后续缓存/落库采用新规则。此需求不批量重算历史分析、不回填其他历史等级、不发送历史告警；用户指定的崩溃样本此前已单独校正，正式界面维持negative。
