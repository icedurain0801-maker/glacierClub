# Discord 授权社区采集机器人设计

**日期：** 2026-09-03  
**状态：** 已确认，待实施计划  
**范围：** 将 Discord 官方 Bot 接入现有 `public-opinion-system`，仅采集由服务器管理员正式授权、并被配置允许的服务器及频道数据。

## 1. 目标与边界

目标是在不新增独立舆情数据模型的前提下，将 Discord 服务器消息、回复、互动和频道结构接入既有“采集源 → 内容入库 → AI 分析 → 告警 → 概览”链路。

首版包含：

- 服务器、分类、频道、线程、角色和成员数量的元数据同步；
- 已授权频道的历史消息分页同步；
- Gateway 实时监听新增消息、编辑、删除、回复、线程和 Reaction 变化；
- 消息正文、附件、链接、回复关系与互动统计入库；
- 复用现有轻量/深度 AI 分析、议题识别、告警与 Public Opinion 概览；
- 采集范围、状态、失败原因和最近同步结果可在现有采集源管理中查看。

明确不包含：

- 用户 Token、Self-bot、绕过权限或规避 Discord 限流；
- 未授权服务器、私密频道或机器人不可见内容；
- 自动发言、私信、管理成员、修改服务器设置；
- 首版的跨服务器全文检索、复杂 Sharding 调度或 Discord 语音内容采集。

## 2. 授权与最小权限

机器人只能通过 Discord Developer Portal 创建的官方 Application/Bot 身份运行，由目标服务器管理员使用 OAuth2 安装链接邀请。

运行前必须启用：

- **Message Content Intent**：读取被授权频道的消息正文；
- **Server Members Intent**：仅在需要成员数量或成员元数据时启用；
- 所需频道权限：`View Channel`、`Read Message History`；
- 若首版不需要机器人回复，不请求 `Send Messages`。

每一个来源配置都必须保存并校验：

- `guildId`：Discord 服务器 ID；
- `channelIds`：允许采集的频道 ID 白名单；
- `threadEnabled`：是否采集白名单频道下的线程；
- `historySyncEnabled`：是否允许历史回填；
- 可选的作者匿名化、保留期限、附件抓取策略。

机器人收到的事件只有在 `guildId` 和 `channelId` 均命中来源配置时才进入后续处理。

## 3. 总体架构

```text
Discord 官方 API
  ├─ Gateway：消息与互动实时事件
  └─ REST：服务器结构、频道、线程、历史消息分页
          │
          ▼
Discord Connector / Adapter
  ├─ 授权范围校验
  ├─ API 限流与退避
  ├─ 标准化 Discord 实体
  └─ 增量游标与断点续传
          │
          ▼
现有同步与导入接口
  ├─ 幂等去重
  ├─ po_contents / 关系数据
  ├─ po_sync_runs
  └─ 来源状态更新
          │
          ▼
现有分析 Worker
  ├─ 轻量分析
  ├─ 条件触发深度分析
  ├─ 议题与负面识别
  └─ 告警生成
          │
          ▼
现有 Public Opinion API / 后台页面
```

实现分为两个独立职责的运行单元：

1. **Discord Gateway 服务**：长期连接 Discord Gateway，接收并缓冲实时事件；断线重连后从持久化游标继续处理。
2. **Discord 历史同步 Worker**：基于 REST API 分页回填频道与线程历史消息，支持断点、去重、重试和限速。

Gateway 不直接写数据库，而是交给统一的标准化入库服务；历史同步也使用同一入库服务，确保实时与回填的幂等规则一致。

## 4. 领域模型映射

Discord 作为现有采集源平台注册：

```text
po_sources
  platform = discord
  source_type = discord_server
  config.guildId
  config.channelIds
  config.threadEnabled
  config.historySyncEnabled
  config.cursorByChannel
  config.retentionDays
  config.anonymizeAuthors
```

内容映射：

| Discord 实体 | 现有字段 / 语义 |
| --- | --- |
| `message.id` | `po_contents.external_id`，来源内唯一键 |
| 频道顶层消息 | `content_type = post` |
| 回复 / Thread 内消息 | `content_type = comment`，保留父消息关联 |
| `message.reference.messageId` | 父级 Discord 消息外部 ID |
| `message.author` | `author_name`；启用匿名化时写稳定哈希别名 |
| 消息正文 | `body` |
| 附件 URL / 图片 / 文件 | `media`，不默认下载私密附件 |
| 消息跳转 URL | `source_url` |
| 创建时间 | `published_at`，统一 UTC |
| Reaction / 回复数 / 附件数 | `engagement` JSON |
| 编辑 / 删除事件 | 更新内容或标记 `is_deleted` |

服务器结构不作为舆情内容写入，而是写入来源配置或同步快照，供来源管理页展示和校验频道白名单。

## 5. 实时事件流程

1. Gateway 建立认证连接，并订阅允许的事件。
2. 收到 `MESSAGE_CREATE`、`MESSAGE_UPDATE`、`MESSAGE_DELETE`、线程或 Reaction 事件。
3. 根据来源的 `guildId`、频道白名单及线程设置过滤；未授权范围立即丢弃。
4. 将事件转换为统一内容 DTO。
5. 依据 `source_id + external_id` 幂等写入；重复投递只更新变化字段和互动统计。
6. 新增或正文变化的消息进入既有分析队列；只更新互动的事件不重复触发全文分析。
7. 成功后持久化频道游标与来源最近成功时间；失败写入稳定错误码和脱敏摘要。

事件处理需要采用串行或按频道有序的队列，避免同一消息的创建、编辑、删除乱序导致回滚。

## 6. 历史同步流程

1. 管理员在来源中启用历史同步并指定白名单频道。
2. Worker 枚举允许频道；可选枚举允许频道的线程。
3. 按 Discord API 分页边界请求消息，保存每个频道或线程的 cursor。
4. 每页先标准化、再以外部 ID 幂等入库。
5. 已导入消息不重复创建；正文或互动变化按更新处理。
6. 每页成功后持久化进度；发生限流、网络失败或进程重启时从最后成功 cursor 恢复。
7. 全部渠道完成后生成 `po_sync_runs` 汇总：发现、写入、新增、变更、未变、更失败数和稳定错误码。
8. 仅本次成功入库、可分析的内容 ID 进入分析范围。

首版历史同步按“最新到最旧”分页，默认设置合理的最大回填时间范围；超出范围需要管理员明确提高历史范围，避免对大型服务器造成长时间 API 压力。

## 7. 可靠性与限流

- 使用 Discord 官方 `discord.js`（Gateway）及其 REST 限流机制；
- 对 HTTP 429 遵守 `retry_after`，不自行提高并发绕过限制；
- 网络错误采用指数退避并限制最大重试次数；
- 用 `source_id + message.id` 建立唯一/幂等约束；
- 处理编辑与删除事件时使用版本时间或事件顺序，避免旧事件覆盖新内容；
- Gateway 断线后使用 Discord 支持的会话恢复机制；无法恢复时重新识别并从持久化游标补偿；
- 需要处理权限撤销、Intent 未开启、频道不可见、机器人被移除等稳定错误码，并在来源管理页提示管理员处理。

## 8. 安全与隐私

- Bot Token 仅通过环境变量或现有凭据管理机制注入；绝不写入代码、日志、日报、接口响应或前端；
- 日志仅记录服务器/频道的内部配置标识、计数、状态码和脱敏错误摘要；
- 默认仅保存必要的公开服务器内容；管理员可设定频道白名单、作者匿名化和数据保留期限；
- 删除事件同步到 `is_deleted`，保留最少的审计字段；
- 不下载或传播附件内容，首版仅记录 Discord 已授权可见的附件元数据与 URL；
- 所有管理端触发的历史同步、授权校验和配置变更均需记录操作来源。

## 9. API 与后台扩展

复用既有 `/sources`、`/contents`、`/overview`、分析和告警 API。新增或扩展：

- Discord 平台枚举和来源配置校验；
- 来源健康检查：Bot 是否在目标服务器、是否能访问白名单频道、所需 Intent 是否可用；
- 来源结构同步：可用频道与线程摘要，用于后台配置白名单；
- 历史同步触发与最近同步结果；
- Gateway 健康状态和最后事件时间。

后台最小新增界面能力：

- 来源类型中选择 Discord；
- 填写 `guildId`、配置频道白名单、选择线程/历史同步/匿名化策略；
- 显示授权和连接健康状态；
- 显示最近一次同步的消息数、变更数、失败数与脱敏错误；
- 继续复用 Public Opinion 页面按来源、社区、时间范围查看聚合数据。

## 10. 测试策略

不使用真实 Bot Token 或真实服务器进行自动化测试。

- 单元测试：Discord DTO 标准化、白名单校验、消息去重、回复映射、编辑/删除合并、匿名化；
- Connector 测试：用 mock Gateway 与 mock REST 响应验证分页、cursor、429 退避、重试和稳定错误码；
- 入库集成测试：验证 `source_id + external_id` 幂等、`po_sync_runs` 计数、分析 eligible ID 范围；
- API 测试：来源配置校验、权限/健康状态、历史同步请求和可见性边界；
- 回归测试：现有 Q1、TapTap 和其他来源连接器不得受 Discord 平台枚举影响；
- 手工验收：在单个管理员拥有的测试服务器中，使用独立测试 Bot 验证安装、频道白名单、历史同步、实时事件、删除同步和后台呈现。

## 11. 分阶段交付

### 阶段 1：平台基础与安全配置

- 添加 `discord` 平台、来源类型和配置 schema；
- 实现 Bot Token 凭据接入及健康检查；
- 实现服务器结构与频道白名单读取；
- 不启用历史同步或实时入库。

### 阶段 2：历史同步与入库

- 实现频道/线程历史消息分页、cursor、限流、幂等入库和同步报告；
- 接入既有分析 eligible ID 范围；
- 可在单一授权测试服务器中验证。

### 阶段 3：实时 Gateway

- 实现实时新增、编辑、删除、回复、Reaction 和线程事件；
- 加入队列顺序、重连恢复和游标补偿；
- 与历史同步共享标准化及入库服务。

### 阶段 4：后台与运营能力

- 完成来源配置与健康状态页面；
- 显示历史/实时同步状态和失败原因；
- 增加数据保留、匿名化及可观测性配置。

## 12. 验收标准

1. 机器人只能在配置并正式授权的服务器/频道读取内容；未命中白名单的事件不会入库。
2. 对一个允许频道执行历史同步时，重复执行不会重复产生内容记录。
3. 新消息在可接受延迟内入库并进入现有分析流程；编辑与删除会正确更新状态。
4. 回复、线程、附件和 Reaction 能以明确语义进入内容与互动字段。
5. Discord 429、授权失效、频道权限不足、Intent 缺失等情况会输出稳定错误码和脱敏提示。
6. Bot Token、原始认证头和不必要的敏感内容不出现在日志、报表或管理端 API 响应。
7. 现有 Q1 与其他采集源回归测试保持通过。
