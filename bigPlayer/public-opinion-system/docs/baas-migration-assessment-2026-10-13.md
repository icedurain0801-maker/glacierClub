## 结论

现有 Glacier BaaS 已实际验证能承接小样本的文档存储、查询、AI 分析与处理状态记录。公开服务端文档和控制台未提供自定义后端代码部署、常驻 Worker、通用定时采集或浏览器运行环境的能力说明。不能据此认定整套系统可以直接迁入 BaaS；目前有证据支持的是“本机采集 + BaaS 数据/AI/查询”的组合。

数据库容量和后台运行能力未确认前，不建议进行正式迁移。文档未列出某能力仅表示尚未获得支持证据，不代表平台绝对不支持。

## 能力与限制

| 项目 | 已确认事实 | 对舆情系统的意义 |
|---|---|---|
| 数据模型 | JSON 文档/集合，非直接暴露 MySQL 表；可指定文档 ID | 需重做关系映射与 Repository，不能直接导入 SQL 当作完成 |
| 查询 | QueryRequest.limit 1～500，默认 50；offset、排序、条件、with_total | 分页可用；全量导出、统计与大型查询需评估 |
| 写入 | 单文档创建、浅合并更新、删除；同 ID 重复创建返回 409 | 有基本文档幂等身份保障，不等于跨文档事务或租约 fencing |
| 权限 | 集合 ACL、角色策略、提交锁定及审计 | 本次 private 集合验证本人读写、无 Bearer 拒绝；游戏/社区权限矩阵未覆盖 |
| 文件 | 官方指引单文件 ≤100MB，私有 OSS + 鉴权下载 | 不代表数据库或应用总容量 100MB，本次未上传文件 |
| 定时任务 | 每应用 ≤10；查询集合/审批流后按模板推送，连续失败 5 次暂停 | 是汇总通知任务，不可等同任意脚本/抓取调度；本次未创建任务或推送通知 |
| 托管 | 控制台明确“纯前端构建产物 zip”，有审批与版本回滚 | 未找到 Node.js API/Worker 部署入口，本次未开通或发布托管 |
| AI | SDK 使用当前人的平台 SSO Cookie 调用 /v1/chat/completions，费用走用户额度 | 单条真实分析成功；无浏览器后台的服务账号、额度、模型兼容、重试限制待确认 |
| 导出/导入 | OpenAPI 有配置与数据 bundle，描述排除 app_secret / 钉钉待办映射 | 具备迁移工具的接口声明，不等于已验证大规模备份恢复/RPO/RTO |

## 容量核实

现有舆情库通过 information_schema 元数据只读估算：41 张 po_ 表，总估算行数 4,768,696（不是内容条数）；数据约 1,089,781,760 字节，索引约 2,077,196,288 字节，总计约 3.17GB（十进制）。这是引擎统计估算，不是逐表精确 COUNT，也不能按原索引大小直接估计 JSON 存储容量。

控制台应用列表只显示文档数，未返回 quota。OpenAPI 存在 `/v1/admin/apps/{app_id}/usage`，声明可返回文档/字节等实际用量与配额；使用本人应用 Bearer 调用返回 401。本次未申请或使用平台 admin key，也未绕过此边界。应用总容量、最大文档体积、集合数、QPS、并发、超时及吞吐上限均待确认。

未做压力测试；三次小文档写入耗时为 197/208/208ms，只是当前低负载样本时延，不是吞吐或容量承诺。

## 做决定前还需平台确认

1. 是否提供任意自定义 API、Node.js/Python 运行环境、常驻 Worker、Cron/队列？请提供官方服务端部署文档、最大执行时长、CPU/内存、外网访问、浏览器支持与服务账号鉴权。
2. 本应用数据库实际配额：文档数、文档/总字节、集合数、QPS、并发、请求大小、超时，以及扩容方式和成本。
3. 跨文档原子事务、唯一约束、CAS/条件更新、租约 fencing、索引与聚合/全文查询能力。现有“内容+feed+checkpoint 同事务提交”不能用多次普通 CRUD 直接替代。
4. 大量历史数据导入/导出吞吐、备份周期、恢复保证、监控与审计保留周期。
5. AI 后台服务身份、额度/计费、批量调用、模型选择、输出契约、缓存/重试及失败告警能力。
6. 补齐真实评论/回复与非管理员权限试验后，再做单来源较大样本和受控负载测试。

后续路线由用户选择：保持现状；仅迁数据/部分 CRUD；或在平台确认完整运行能力后分阶段全迁。任何正式迁移、数据切换、生产配置和服务发布均不包含在本次评估授权内。
