- 日期：2026-09-09

- 状态：待开发阶段性交付后执行

- 本次动作：仅制定验收矩阵与证据需求，未启动 Worker、未进行外部采集、未写入业务数据。

## 验收前置条件

1. 提供可控时钟或可注入 `Asia/Shanghai` 时间的调度测试入口，禁止依赖真实等待至 02:00。
2. 提供最少四个隔离测试来源：境内 BigPlayer、境外 Discord、已授权但未接入连接器的平台、授权失效或连接器失败来源。
3. 每项测试可查询数据库任务记录、来源调度状态 API、任务记录 API、来源管理页面；同一来源的测试数据须可按 `source_id` 清理或在独立测试库执行。
4. 测试运行必须禁用真实外部连接器调用，使用可观测的受控连接器桩；桩返回不等于连接器未接入。

## 功能矩阵

| 编号 | 场景与输入 | 核心断言 | 数据库证据 | API / 页面证据 |
|---|---|---|---|---|
| S-01 | 1 小时来源，业务日 02:00 | 生成 `scheduled` 任务，计划时刻为 02:00，窗口为前一自然日 | 唯一任务含来源、计划时刻、触发方式和窗口 | 来源显示下次 03:00；任务记录显示计划/实际时间和窗口 |
| S-02 | 1 小时来源，02:59/03:00/03:01 | 仅在 03:00 槽生成任务，不因完成耗时漂移 | 02:00、03:00 各一条，无非槽时间 | 下次计划与 API 相同，均为固定时刻 |
| S-03 | 15 分钟、6 小时、12 小时、24 小时频率 | 分别命中 02:15、08:00、14:00、次日 02:00 规则；24 小时每日仅首槽 | 每个来源只存在对应固定槽记录 | 页面按北京时间展示频率和下次计划 |
| S-04 | 01:59、02:00、次日 01:59、次日 02:00 | 业务日边界严格为 `[02:00, 次日 02:00)` | 首槽不跨错业务日、无重复 02:00 | API 返回的计划时间与页面完全一致 |
| S-05 | 服务错过至少 3 个槽后恢复 | 每来源只补当前之前最近一个未处理槽，触发方式 `scheduled_catchup` | 无更早漏槽批量入队 | 最近结果/计划时刻可解释单次补跑 |
| S-06 | 当日锚点后新来源或新授权默认账号 | 首次满足准入后立即补最近一个槽一次 | 一条 catchup，非历史回放 | 来源显示可调度及下一未来槽 |
| S-07 | 相同 `source_id + scheduled_at + trigger_type` 连续扫描 10 次 | 仅产生一条任务 | 唯一键、任务总数均为 1 | API/页面只显示一条对应计划记录 |
| S-08 | 同来源已有有效 `running` 租约时到达新槽 | 不并发创建或执行第二任务，记录 `PREVIOUS_RUN_ACTIVE` | 无第二有效运行租约；跳过记录可追溯 | 任务记录/最近结果显示稳定跳过原因 |
| S-09 | 不同来源同槽同时到达 | 可按来源并发上限运行，互不串扰 | 每个来源独立任务和租约 | 各来源状态独立更新 |
| S-10 | 来源/默认账号授权失效、账号缺失、归属不匹配 | 不创建伪成功任务；使用 `ACCOUNT_NOT_FOUND`、`OWNERSHIP_MISMATCH` 或授权错误 | 无 completed 记录；跳过/失败原因稳定 | 列表显示不可调度及脱敏原因，下次为 `--` |
| S-11 | 平台未接入连接器或能力不支持 | `CONNECTOR_NOT_FOUND`/能力错误；不得调用桩或标成功 | 无成功任务和内容写入 | 页面显示不可调度/连接器不可用 |
| S-12 | 一个来源网络超时、限流、不可重试失败；另一个来源正常 | 可重试错误最多 3 次指数退避；失败不阻塞其他来源；不可重试不重试 | 失败来源终态与次数正确；正常来源 completed | 任务记录展示稳定错误码；其他来源正常完成 |
| S-13 | 停用来源、账号、社区或游戏后到达槽 | 不产生新任务；既有历史可查 | 无新 planned/queued/running 任务 | 来源不可调度，历史任务仍可筛选 |
| S-14 | 已保存频率从 1 小时改为 6 小时 | 保存后仅从下一个未来槽生效，不追溯旧槽 | 配置版本/生效时间、下一个槽正确 | 保存响应 `nextScheduledAt` 与页面一致 |
| S-15 | 手动同步夹在固定槽之间 | 只创建 `manual`，不占用或重置 fixed slot | manual 计划时刻为空；scheduled 槽仍存在 | 任务记录区分触发方式 |
| S-16 | 境内 BigPlayer 与境外 Discord 同一扫描 | 两者均通过同一调度入口按各自频率入队 | 任务归属、平台、区域正确，无平台专属重复任务 | 列表/记录可按区域、平台还原两来源状态 |
| S-17 | 后台页面切换区域、社区、平台筛选 | 仅影响展示，不缩小后台全区域扫描范围 | 扫描批次仍覆盖全部合格来源 | 当前筛选外来源仍在 API/任务记录全量视图存在 |

## 必须暴露的可观测证据

| 层级 | 必需字段 / 能力 | 用途 |
|---|---|---|
| 调度器日志 | scan ID、北京时间、候选来源数、准入/拒绝原因、命中时刻槽、入队/跳过/租约决定 | 定位“应跑、为何未跑”，日志不得含凭据 |
| 数据库 | source ID、配置版本/生效时间、scheduled_at、trigger_type、状态、租约、尝试次数、稳定错误码、窗口、实际起止时间 | 验证幂等、互斥、漏点、重试和跨日 |
| 来源 API | 调度状态、不可调度原因、nextScheduledAt、lastScheduledAt、最近结果、时区/锚点 | 与来源列表口径对齐 |
| 任务 API | 来源/平台/区域快照、计划时刻、触发方式、窗口、状态、计数、错误码 | 与任务记录页面和数据库对齐 |
| 页面 | 来源列表的授权、调度状态、频率、下次采集、最近同步/结果；任务记录的计划时刻与触发方式 | 验证管理员可还原证据链 |
| 连接器桩 | 被调用次数、来源/窗口、成功/超时/限流/不可重试结果 | 验证调用边界与失败隔离，不触发外部采集 |

## 端到端签核口径

每个核心场景须同时满足：数据库任务记录、对应 API 响应和后台页面显示三者的来源归属、计划时刻、触发方式、状态、错误码一致。任一层出现 `completed` 而连接器未接入、未被调用或授权闸门未通过，判为 P0 缺陷。

## 当前阻塞项

开发交付前需确认：受控时间入口、测试库清理机制、连接器桩注入方式、任务/来源 API 字段和页面入口。上述任一项缺失时，只能完成单元级验证，不能执行 PRD 第 8 节要求的本机三端端到端验收。
