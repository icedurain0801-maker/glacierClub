## A. TapTap：预算耗尽修复

### A-1 近七天边界与真实 run

1. 进入 TapTap source 对应的抓取任务记录页，筛选北京时间近七天。
2. 打开开发提供的修复后 run 详情，确认页面显示实际起止时间、source/platform 和最终状态。
3. 验证不再出现 `SYNC_PAGE_BUDGET_EXHAUSTED`；若仍出现，直接 FAIL（P1）。
4. 若页面展示分页/页数/处理统计，记录抓取页数与最终 `inserted`、`changed`、`skipped/duplicate` 或等价字段。

### A-2 新内容落库与页面可见

1. 在抓取内容管理页按该 TapTap 社区和“今天”筛选，确认本次 run 的新增内容可见。
2. 打开至少一条新增内容详情，核对标题、来源平台、发布时间和 source 归属。
3. 切换“昨天”，确认不会把今天新增内容错误归入昨天。
4. 切换“近七天”，确认新增内容落在范围内，列表和总数与页面筛选一致。

### A-3 历史重复执行

1. 对同一修复后 run 的历史范围打开页面记录（不发起新 run），核对已有历史内容不重复展示。
2. 以内容唯一标识、标题+发布时间（页面可见字段）抽查至少 3 条历史记录，记录是否重复及 `duplicate/skipped` 统计。
3. 若同一内容出现两条独立记录，FAIL（P1）；若页面无唯一标识或统计字段，标记“证据不足”，退回开发补充可观测证据。

## B. 境内 BigPlayer：今日零新增修复

### B-1 今天/昨天/近七天筛选

1. 打开 source `5c21f78d-5f67-4467-963d-dcdeb5e26cab` 对应的抓取任务记录与抓取内容管理页。
2. 分别选择北京时间“今天”“昨天”“近七天”，每次记录页面实际日期范围、列表总数和当前页数据。

### B-2 新内容、历史去重与归属

1. 在“今天”列表打开至少 1 条开发提供的新增内容，核对来源为 BigPlayer 社区、社区为境内目标社区、发布时间为北京时间今天。

### B-3 run 终态

1. 在任务记录页打开开发提供的修复后 run，记录开始/结束时间、终态、失败原因（如有）、新增/变更/重复统计。
2. 终态必须稳定，不得停留“运行中”或刷新后回跳；不得出现旧的日期零新增误报。
3. 关闭详情、刷新页面后重新打开同一 run，确认终态和统计保持一致。

## 证据要求

每项用例记录：测试时间、页面 URL、环境、region/community/platform、sourceId、筛选范围、runId（页面可见时）、页面截图/文本、内容详情抽查、终态统计、控制台最近 50 条错误/警告。

以下证据缺一不可，否则结论只能是“未完成/FAIL”：

- 页面实际展示的新内容或历史内容；
- 页面可见的 run 终态；
- inserted/changed/去重等页面统计或明确的等价字段；
- 今天/昨天/近七天筛选结果；
- 刷新后状态和内容仍一致。
