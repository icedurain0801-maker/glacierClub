# v205 BigPlayer H5 多站点链接：验收准入矩阵

- 状态：等待开发返件，**未执行真实配置/采集，未判 PASS**。
- 范围：仅 `bigplayer_h5`。Discord、TapTap、Facebook 的来源合同与运行行为必须保持不变。
- 验收方式：开发定向回归 + 受控真实三链接配置的 API、MariaDB、Worker 日志、管理页四证；禁止 Mock 替代真实请求。

## 已覆盖

- N 个有效 H5 链接产生 N 个独立子任务，父运行汇总。
- 单链接超时、限流或解析失败不取消同父的其他子任务。
- UTC 租约、并发、checkpoint、有界补跑既有修复不可回退。
- 管理页支持新增、修改、移除和结果明细；批量授权/能力检测允许部分失败。

## 待确认

| 事项 | 建议确认口径 |
|---|---|
| 链接规范化与重复 | 明确 URL 去 hash、尾斜杠、大小写、默认 query、重定向后的唯一键；同一规范链接在同一 source/account 下只能一条。 |
| 修改/移除在途链接 | 明确在途子任务是继续使用创建时快照、取消，还是进入待人工验证；不得把结果写入新链接。 |
| 父运行终态 | 明确全部成功、部分成功、全部失败、零授权范围、子任务未启动时的父状态、错误码和汇总计数。 |
| 链接 credential 归属 | 明确一个 source 共享 credential 还是按链接独立绑定；批量授权部分失败时是否可仅启用成功链接。 |
| 存量 `baseUrl` 迁移 | 明确回填的新链接 ID 稳定性、迁移失败回滚、历史 run/content 的来源映射不变。 |

## 缺失/风险

1. 需要业务唯一键 `(source_id, account_id, normalized_link, window, cursor_or_segment)`，既允许不同链接并发，又拒绝同链接同窗同 cursor/segment 重复 claim。
2. 父/子计数不能混用：子任务 fetched/stored/inserted/changed/unchanged 与父汇总应可复算；内容仍按既有业务键幂等。
3. 删除或禁用链接不能删除历史内容、checkpoint、run 明细；仅阻止后续调度。迁移不得重抓或覆盖既有 `baseUrl` 历史语义。
4. Worker restart、lease lost、deadline、timeout、rate limit 必须按子任务隔离；父任务不能因一个子任务的 abort signal 取消其余链接。
5. B 端列表、编辑表单、运行记录、详情、筛选和 API 必须展示一致的链接数、子任务状态及错误原因，避免仅父状态“完成”而隐藏部分失败。

## 建议补充的验收用例

| 优先级 | 前置条件 → 操作 | 预期结果 |
|---|---|---|
| P0 | 一个 BigPlayer source/account 配置 3 条真实有效且互不重复链接 → 保存并手动有界同步 | DB 有 1 父 + 3 子任务；3 个真实请求；每子任务独立 lease/checkpoint/deadline；父汇总与子项可复算。 |
| P0 | 同一链接同窗同 cursor/segment 并发双提交 → 同时领取 | 仅一个子任务/claim 成功；另一方稳定复用或拒绝；不重复请求、不重复内容。 |
| P0 | 同一父的 3 链接中分别注入可控超时、限流、正常返回 → 执行 | 故障子任务保留稳定原因；正常子任务完成；父为明确部分终态，不取消健康任务。 |
| P0 | Worker 在至少一个子任务提交 checkpoint 后重启 → 恢复 | 每链接从自己的 cursor/segment 续跑；不从头、不卡死、父汇总无重复。 |
| P0 | 配置合法链接、重复链接、空值、非 H5 host、非法 URL → 保存 | 仅有效非重复链接持久化；错误定位到具体输入；原有有效配置不被部分失败覆盖。 |
| P1 | 由单 `baseUrl` 升级 → 打开/保存/同步 | 自动生成一条等价子链接；历史 run/content 可查询；回滚与重复迁移幂等。 |
| P1 | 修改、移除、禁用一个已配置链接 → 查询历史并等待后续调度 | 新配置仅影响未来子任务；历史 run/checkpoint/content 与明细保留；在途行为遵循已确认口径。 |
| P1 | 批量授权/能力检测三个链接且其中一条失败 → 查看 B 端/API | 成功链接可用，失败链接显示原因；父/来源不被错误标为全成功。 |
| P1 | 分别运行 BigPlayer、Discord、TapTap、Facebook 回归 | 非 BigPlayer API、配置、调度、内容计数和页面不发生契约变化。 |
