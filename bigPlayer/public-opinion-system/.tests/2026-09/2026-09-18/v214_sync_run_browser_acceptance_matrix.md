# v214 同步任务真实浏览器验收矩阵

- 状态：待开发交付可控验证环境后执行
- 测试环境：待开发提供；不得使用真实采集 run
- 执行边界：本矩阵不授权创建采集、填入凭据、保存配置或对生产数据执行破坏性操作。

## 进入条件

1. 开发提供可控验证环境、测试社区与可重复使用的测试采集源。
2. 可控环境能够创建一条标识明确的测试 run，并支持进度、暂停、继续、取消和网络故障注入。
3. 开发提供 run 标识、预期计数变化规则、轮询/推送机制、断网注入方式与恢复判定。
4. 测试前记录基线：sources、collection-runs、content、overview、alerts、keywords 六页的初始计数、时间与 URL。

## 开发离线交接说明

- 可控环境 URL：待项目经理另行授权后提供；本变更未启动本机或外网服务，QA 不得以生产、3000 Mock 或真实 provider 替代。
- 专用资产：仅允许独立测试社区、独立测试来源和明确标识的测试账户；不得使用现有业务来源、凭据或生产内容。开发未创建这些资产。
- run 标识：由受控环境预置或创建后记录 UUID；同一用例只复用该 UUID，不以重新发起同步替代 pause/resume/cancel 验证。
- 计数规则：`fetched_count` 为已拉取项目数，`inserted_count/changed_count/unchanged_count` 为本页写入分类，`stored_count=inserted_count+changed_count`；暂停和取消后各计数与 checkpoint cursor 必须冻结，resume 从保存 cursor 继续。
- 断网注入：仅浏览器开发者工具 Offline 或受控代理阻断 API 请求；不停止 worker、不改数据库、不向 provider 发请求。恢复后以 `GET /sync-runs/:id` 为权威状态，不能依据本地 dock 文案判定。
- 恢复判定：显式 `paused -> queued -> running` 后计数只可从冻结点增加；`cancelled` 刷新后仍为终态，不能进入 runnable 队列或自动恢复。

## 主流程矩阵

| 编号 | 场景 | 浏览器操作 | 期望结果 | 状态 |
|---|---|---|---|---|
| SR-01 | 开始至进度 dock | 在可控环境开始指定测试 run | 出现同一 run 的进度 dock；run ID、状态、已处理/总数或等价进度可读 | 待执行 |
| SR-02 | 跨页保持 | 开始后依次切换 sources、collection-runs、content、overview、alerts、keywords | 每页均关联并显示同一 run，不重复创建 dock/run；返回任一页仍定位到该 run | 待执行 |
| SR-03 | 跨页刷新 | 在六页分别强刷 | 仍显示同一 run；不丢失状态或误建新 run | 待执行 |
| SR-04 | 计数更新 | run 运行期间记录 sources 同步状态、collection-runs 进度、content 内容量、overview 指标、alerts、keywords 相关计数 | 与开发提供的计数规则一致；更新时间单调推进或有明确刷新语义 | 待执行 |
| SR-05 | 暂停冻结 | 进度发生变化时暂停 run，跨页观察并等待一个调度周期 | 状态为 paused；进度和计数冻结；不得继续自动增长 | 待执行 |
| SR-06 | 继续恢复 | 对 paused run 执行继续，跨页观察 | 状态恢复 running；进度从冻结点继续，计数按规则恢复更新 | 待执行 |
| SR-07 | 取消确认 | 对运行中或暂停中的 run 发起取消，并在确认框中确认 | 状态为 cancelled；进度/计数停止；刷新、跨页、重新打开 dock 后均不自动恢复 | 待执行 |
| SR-08 | 关闭仅收起 | 运行中关闭 dock，再切换页面或回到 collection-runs | dock 仅收起，run 继续且可重新打开；不应触发暂停或取消 | 待执行 |

## 记录格式

每个用例记录：测试时间、环境、run ID、页面 URL、操作前后状态与计数、截图、控制台结果、PASS/FAIL、缺陷等级。任何与数据增长、状态机或跨页一致性有关的 FAIL 均退回开发负责人，不在本会话修改业务代码。
