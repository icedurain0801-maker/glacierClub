# 楼层抽奖 · 活动类型扩展 PRD

> 模块：bigPlayer / 社区运营 / 楼层抽奖管理
> 版本：v002（2026-05-18）
> 关联文件：[FloorLotteryManage.html](../../../../bigPlayer/admin/community/FloorLotteryManage.html)

---

## 一、需求简介

楼层抽奖原仅支持**一次性开奖**的活动形态，无法满足"连续 N 天/N 周打卡型"运营场景。本次新增「活动类型」维度，将楼层抽奖拆分为**单次活动**与**周期活动**两类，并同步引入：

1. **发奖方式**字段（人工审核 / 自动发奖），用于决定开奖后的执行链路；
2. **周期活动**完整配置体系（活动时段、固定 24:00 自动发奖、周期总数、活动说明）；
3. 评论关键词在周期活动下的**匹配类型**联动（统一 / 按周期配置），支持按周期下发不同关键词。

目标：用同一个表单覆盖"一次性抽奖"与"长周期打卡抽奖"两种核心运营玩法，降低运营创建活动的学习成本。

## 二、字段总览

### 2.1 基础信息区

| 字段 | 类型 | 必填 | 适用类型 | 说明 |
|---|---|---|---|---|
| 活动类型 | 单选 | 是 | 全部 | `单次活动` / `周期活动`，默认单次活动，**创建后不可修改** |
| 活动名称 | 文本 | 是 | 全部 | 沿用原规则 |
| 活动时间（单次） | 日期+时间 | 是 | 单次 | 即「活动截止时间」，到点触发一次开奖 |
| 活动时间（周期） | 日期段 | 是 | 周期 | 见 §3.1，**创建后不可修改** |
| 开奖人数 / 周期总数 | 数字 | 是 | 全部 | 单次=开奖人数；周期=**每个周期**的开奖人数（label 动态切换），周期总数**创建后不可修改** |
| 发奖方式 | 单选 | 是 | 全部 | `人工审核`（默认） / `自动发奖`，见 §3.2 |
| 活动说明 | 富文本/多行文本 | 否 | 全部 | ≤ 200 字 |

### 2.2 参与条件区（评论关键词联动新增字段）

| 字段 | 类型 | 必填 | 显示条件 | 说明 |
|---|---|---|---|---|
| 匹配关键词 | 单选 | 是 | 勾选「评论关键词」 | `精准匹配` / `模糊匹配` / `不限` |
| 关键词显示 | 开关 | 是 | 勾选「评论关键词」 | 是否在 C 端展示关键词提示 |
| **匹配类型** | 单选 | 是 | **周期活动 + 勾选评论关键词 + 匹配关键词 ≠ 不限** | `统一`（默认）/ `按周期配置`，本次新增 |
| 关键词列表 | tag | 是 | 单次活动 或 周期+统一 | 沿用原 tag 输入逻辑 |
| 周期关键词表格 | 表格 | 是 | 周期活动 + 按周期配置 | 见 §3.3 |

## 三、关键字段详细规则

### 3.1 活动时间（周期活动）

整合为一个表单块：

- **活动时段**：`开始日期 — 结束日期`，系统据此自动计算周期数（默认按"天"切分，1 天 = 1 周期），并在右侧实时显示 `共 X 天 · X 个周期` 徽标。
- **发奖时间**：前端不提供单独配置项；每个周期的 `24:00` 自动发奖。
- **修改约束**：活动创建成功后，活动时段不可修改。
- **联动**：切换活动时段，下方"按周期配置关键词表格"会自动重新生成周期行，**旧周期已填关键词需重新录入**（前端会提示确认）。

### 3.2 发奖方式

| 取值 | 行为 | 适用场景 |
|---|---|---|
| 人工审核（默认） | 到达开奖时间生成预选名单，**运营手动确认**后才发奖 | 高价值道具、需要风控审核 |
| 自动发奖 | 到达开奖时间系统自动从达标玩家中随机抽取 N 人并直接发奖 | 低价值固定道具、纯激励玩法 |

- **周期活动 + 自动发奖**的附加提示：每个周期的 `24:00` 系统自动开奖并发奖；**若达标人数 M < 开奖人数 N，则实际发放 M 个，剩余名额不补发**。
- 列表页新增「发奖方式」标签列展示两种模式。
- 编辑约束：**未进入发奖流程**前可改，进入发奖流程或已发奖后锁定不可改。

### 3.3 评论关键词 · 按周期配置（周期活动专属）

触发条件三段联动：`活动类型=周期 && 勾选评论关键词 && 匹配关键词∈{精准匹配, 模糊匹配}`，才会出现「匹配类型」单选；选择 `按周期配置` 后展开关键词表格：

| 列 | 说明 |
|---|---|
| 周期 | 系统按活动时段自动生成（如 `周期1：2026-05-20`），不可编辑 |
| 关键词 | 每行支持以 tag 形式录入**多个**关键词，至少 1 个，**必填** |

- 表格超过 N 行时折叠，提供「展开全部」操作。
- 切到 `统一` 模式：复用单次活动的关键词 tag 输入区，所有周期共用一组关键词。
- `匹配关键词=不限` 时：匹配类型行与关键词输入区**整行隐藏**。

## 五、异常场景与校验规则

### 5.1 表单校验

| 场景 | 规则 |
|---|---|
| 活动类型未选 | 提交拦截：`请选择活动类型` |
| 周期活动 · 活动时段开始日 ≥ 结束日 | `结束日期必须晚于开始日期` |
| 周期活动 · 活动时段早于当前日期 | `活动开始日期不可早于今天` |
| 周期活动 · 周期总数 = 0 | `当前活动时段无有效周期，请调整日期范围` |
| 开奖人数 ≤ 0 或非整数 | `开奖人数需为大于 0 的整数` |
| 评论关键词勾选但关键词为空（统一模式） | `请至少添加 1 个关键词` |
| 按周期配置存在任一周期关键词为空 | `周期 X 的关键词未填写`，定位高亮该行 |
| 活动说明 > 200 字 | 输入框前置截断 + 计数器红色提示 |

### 5.2 运行期/编辑期约束

| 场景 | 行为 |
|---|---|
| 已创建活动改活动类型 | **禁止**，字段置灰，hover 提示 `活动类型创建后不可修改` |
| 已创建活动改活动时间 | **禁止**，字段置灰，hover 提示 `活动时间创建后不可修改` |
| 已创建活动改周期总数 | **禁止**，字段置灰，hover 提示 `周期总数创建后不可修改` |
| 已创建活动改按周期配置评论关键词 | **禁止**，字段置灰，hover 提示 `按周期配置评论关键词创建后不可修改` |
| 已进入发奖流程改发奖方式 | **禁止**，字段置灰 |
| 已创建活动切换匹配类型（统一↔按周期） | **禁止**，字段置灰，避免影响按周期配置评论关键词 |
| 按周期配置下，重新生成周期行导致关键词丢失 | 弹窗 `检测到周期发生变化，旧关键词将被清空，是否继续？` |
| 自动发奖 · 达标人数 M < 开奖人数 N | 实发 M 人，剩余名额不补发，开奖记录标注 `名额未满` |
| 自动发奖 · 达标人数 = 0 | 当期流标，记录状态 = `流标`，不消耗道具库存 |
| 评论关键词大小写/全半角 | 模糊匹配统一**忽略大小写、全半角归一化**；精准匹配亦做归一化但保留 emoji 原样 |

### 5.3 数据兼容

| 场景 | 处理 |
|---|---|
| 历史楼层抽奖数据（无活动类型字段） | 视为 `单次活动`，无发奖方式则默认 `人工审核` |
| 历史活动 OPS 后台展示 | 列表页发奖方式列展示 `人工审核` 兜底标签 |

## 六、列表页变更

- 新增列：**活动类型**（单次 / 周期）、**发奖方式**（人工审核 / 自动发奖）
- 周期活动在「活动时间」列展示 `2026-05-20 ~ 2026-06-10 · 共 22 周期`，单次活动展示单一截止时间。
- 详情入口、操作权限沿用现有规则；进行中的周期活动支持「查看每期开奖结果」二级入口（本期范围外）。
