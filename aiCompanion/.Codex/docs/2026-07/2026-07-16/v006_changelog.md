# v006 changelog

## 背景
- 用户反馈 Excel 原表中存在“联盟最多可容纳100名成员，并分为5个阶级”这类内容，但 AI 回答无法命中。

## 根因
- 问题不在回答模型本身，而在 RAG 检索链路。
- 目标内容已入库在 `knowledge_entries.id = 6919`，但原检索流程存在三处问题：
  1. 语义检索更容易命中 FAQ 等泛化条目。
  2. 词法兜底依赖数据库 `LIKE`，对这类中繁混排长文本命中不稳定。
  3. 候选在真正重排前被提前截断，导致正确条目被裁掉。

## 本次修改
- 重写 `server/src/services/ragContext.js` 的检索策略：
  - 增加 query token 提取、简繁变体扩展、词法打分。
  - 词法兜底改为版本内条目内容的 Node 侧匹配与排序，不再依赖 SQL `LIKE` 截断候选。
  - snippet 改为围绕命中事实截取，而不是固定截前 200 字。
  - 增加“人数上限”类问题的意图对齐重排，压制“帮助次数上限 / 参赛人数 / 城市数量”等串题结果。
- 补充 `server/test/ragContext.test.js`，覆盖：
  - 弱语义命中时的词法救回；
  - 相关 snippet 截取；
  - 人数上限问题的意图重排抑制误召回。

## 验证
- `node test\\ragContext.test.js` 通过。
- 实测 `ragContext.retrieve(1, '联盟最多可以有多少人', 5)` 当前返回首条且唯一条目为 `entryId = 6919`。
