02
📱 移动端方案
中转页 + 深度链接，覆盖已安装与未安装两种路径
2.1 · 流程步骤
1. 分享邀请
玩家在游戏内分享邀请链接到微信、QQ、朋友圈等
2. 打开链接
被邀请人打开分享链接（前端处理的中转页）
3. 下载游戏
点击下载按钮，前往对应应用商店下载
📌 应用商店下载完成后会回到中转页
4. 启动游戏
点击启动按钮，将邀请人 UUID + 角色 ID + 被邀请人 UUID + 角色 ID 作为启动参数传入 APK
5. 后端绑定
平台后端接收参数后，将两个玩家对象绑定，并提供通用查询接口
6. 定时查询
游戏通过平台查询接口定时抓取邀请状态，以及被邀请人的累计账号充值额
7. 返利发放
游戏根据拉取到的累计充值额，自行计算返利档位并发放奖励给邀请人
⚠️ 奖励由游戏侧发放，平台只提供数据，不参与发奖
2.2 · 深度链接技术方案
📖 整体机制
🔗
邀请者分享专属深度链接
链接中携带邀请者的 uuid、角色 ID、账号 ID
✅
已安装 App
点击链接直接唤起 App，参数随启动 Intent / URL 一并传入
📥
未安装 App（延迟安装）
先引导至应用商店下载，用户首次打开 App 时再尝试获取参数
🛠 实现步骤
1️⃣
生成专属链接
用户分享时，App 向服务端请求生成一个包含邀请者标识的专属深度链接（暂定）
https://yourdomain.com/invite?inviter_id=123
2️⃣
配置 App · iOS
配置 URL Schemes；在 AppDelegate 中处理
application(_:open:options:) 或
application(_:continue:restorationHandler:)
解析传入 URL 中的参数
2️⃣
配置 App · Android
配置 Intent Filter（支持 http/https 的自定义 Scheme）；在 Activity 的 onCreate 或 onNewIntent 中通过 getIntent().getData() 解析传入 URI 中的参数
3️⃣
传递参数
• 直接唤起：App 被唤起时，直接从启动 Intent / URL 中解析出 inviter_id
• 延迟安装：借助剪贴板来传递参数
⚠️ 无剪贴板权限则无法完成绑定，此情况运营已知悉，不需要额外处理
4️⃣
上报绑定关系
App 获取到 inviter_id 后，在用户首次启动的节点，将其与新用户的 user_id 一同发送给服务端，记录邀请关系
2.3 · 中转页按钮交互
📥 下载游戏
🔗
跳转应用商店
根据设备系统（iOS/Android）跳转至对应的官方应用商店
⬅️
自动返回中转页
用户在应用商店完成下载后，系统会自动返回中转页
✅
继续启动
用户可点击「启动游戏」进行安装或直接启动游戏
💡 关键处理
需配置应用商店返回链接，确保用户能正确回到中转页而非被困在商店内
🚀 启动游戏
🎮
调用 DeepLink 启动
通过 URL Scheme 或 DeepLink 启动已安装的游戏应用
📦
拼接启动参数
在 URL 中包含邀请人和被邀请人的 UUID 与角色 ID
🔄
游戏接收绑定
游戏解析参数后，向平台后端发送邀请关系绑定请求
📌 参数格式
game://invite?inviter_uuid=xxx&inviter_role_id=yyy&invitee_uuid=aaa&invitee_role_id=bbb
⋯ 点击右上角「更多」
💬
弹出教程提示
显示步骤指引：「点击右上角 ⋯」「选择在浏览器中打开」
🌐
浏览器打开
确保用户用系统默认浏览器打开中转页，而非 WebView 内打开
🎯
修复跳转问题
避免在微信/QQ/小红书等 APP 内打开时应用商店跳转失败
⚠️ 使用场景
当用户在社交 APP（微信/QQ/抖音等）内打开邀请链接时，这些 APP 会用内置浏览器打开，导致应用商店跳转被拦截。此时需要用户手动点击右上角菜单，选择「在浏览器中打开」才能正常跳转
03
🎮 小游戏端方案
参数写入分享卡片，无需中转页与深度链接
3.1 · 流程步骤
1. 生成分享卡片
游戏直接将邀请人 UUID + 角色 ID 写入分享卡片参数
🚀 流程更简洁，无需中转页
2. 点击卡片
被邀请人点击邀请卡片或链接
3. 上传绑定
立即上传自己的 UUID + 角色 ID，以及邀请人的 UUID + 角色 ID 给平台后端
4. 后续流程
平台后端绑定、游戏查询、返利计算的流程与移动端一致
3.2 · 与移动端的差异
🚫
无需中转页
不存在应用商店下载与返回环节，省去「下载游戏 / 启动游戏」两个按钮
🚫
无需深度链接与剪贴板
参数直接写在分享卡片里，不涉及 URL Scheme / Intent Filter，也不依赖剪贴板权限
✅
后端流程一致
绑定邀请关系、状态查询接口、按充值额返利，与移动端复用同一套后端能力
04
🔌 平台查询接口
供游戏服务端定时拉取邀请关系与充值数据
4.1 · 📤 返回字段
👤
邀请人标识
inviter_uuid、inviter_role_id、inviter_account_id
🙋
被邀请人标识
invitee_uuid、invitee_role_id、invitee_account_id
💰
被邀请人累计账号充值额
按账号维度统计的累计充值总额（非单角色、非单笔），游戏据此计算返利档位
🕐
绑定信息
绑定状态、绑定时间，用于游戏侧判断邀请关系是否生效
📌 职责边界
平台只负责「绑定关系 + 充值额统计」的数据输出；奖励发放规则、档位与到账全部由游戏侧处理，平台不参与
4.2 · 🔄 调用方式
⏱
定时轮询
游戏服务端定时调用该接口，拉取邀请状态与最新累计充值额
🔁
通用接口
移动端与小游戏端复用同一接口，游戏侧无需区分来源
05
关键角色与职责
各环节的分工边界
🌐
中转页（前端）
承载下载引导与启动唤起，处理应用商店跳转与返回
📦
启动参数
包含邀请人与被邀请人的 UUID、角色 ID、账号 ID
🖧
平台后端
绑定邀请关系，提供统一查询接口，输出邀请状态与被邀请人累计账号充值额。不参与奖励发放
🎮
游戏服务端
定时调用查询接口抓取邀请状态与累计充值额，自行制定返利规则并发放奖励
