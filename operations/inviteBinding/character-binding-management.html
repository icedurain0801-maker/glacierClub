需求说明
角色绑定管理 · 需求说明
周期活动 老带新 邀请绑定 两级页面

一、业务背景

游戏「老带新」周期活动：邀请人邀请被邀请人进入游戏，被邀请人完成首次登录后绑定到邀请人名下，邀请人据此获取邀请奖励。本页面用于后台记录该绑定关系，并按活动周期独立结算，下一期清零重算。

二、核心目标

  • 支持创建周期活动，每次活动数据独立归当次活动，下一期清零重算。
  • 记录每次绑定关系：邀请人/被邀请人角色ID、邀请人/被邀请人冰川通行证ID、被邀请人设备ID、绑定时间。
  • 提供绑定记录的查询、查看与导出能力（本页为只读，不做解绑等修改操作）。

三、页面结构（两级页面）

外层为活动列表页，内层为绑定明细页，同文件内通过 view 切换。

  • 活动列表页：顶部为活动ID + 活动名称筛选；【创建活动】按钮位于列表左上角；表格列为活动ID/活动名称/规则说明/创建时间/状态/有效绑定/操作（详情/结束）；规则说明列超长时省略号截断，鼠标悬停显示完整内容；带分页器。
  • 绑定明细页：点击活动列表"详情"进入；顶部为"返回活动列表"按钮 + 当前活动名 + 活动状态摘要（活动ID/状态/创建时间/有效绑定数）；筛选栏为ID类型下拉+输入框、绑定状态、绑定时间范围；表格列为绑定ID/邀请人角色ID/邀请人通行证ID/被邀请人角色ID/被邀请人通行证ID/被邀请人设备ID/绑定时间，列宽均分；带分页器与导出。

四、数据模型与ID规则

活动字段活动ID、活动名称、创建时间、状态(进行中/已结束)、奖励规则、规则说明、有效绑定数
绑定记录字段绑定ID、活动ID、邀请人角色ID、邀请人通行证ID、被邀请人角色ID、被邀请人通行证ID、被邀请人设备ID、绑定时间、绑定状态(有效/已解绑)、解绑时间、解绑原因
活动ID规则从 100 开始自增（100、101、102…），纯数字无前缀
绑定ID规则从 10000 开始自增（10000、10001…），纯数字无前缀
角色ID/通行证ID均为纯数字（如 8800123、465486750），无字母前缀

五、交互逻辑

  • 活动列表：按活动ID/活动名称本地过滤；点击"详情"进入该活动绑定明细页；新建活动后刷新列表。
  • 筛选栏（活动列表页与绑定明细页）均仅提供「查询」按钮，不设重置按钮；需要恢复全量时，手动清空筛选项后点击查询即可。
  • 绑定明细：切换活动 → 重新渲染该活动记录 + 更新状态摘要；返回活动列表 → 回到外层。
  • 查询：按「ID类型 + 输入值」「绑定状态」「绑定时间范围」组合过滤，各条件之间为且关系；字段明细见下方「七、筛选字段说明」。
  • 导出：当前筛选结果导出 CSV（UTF-8 BOM）。
  • 进行中活动可点击"结束"，经二次确认后状态变为已结束，绑定记录仍仅支持查询、查看与导出。
  • 本页绑定记录为只读：仅提供查询、查看与导出，不提供解绑等修改操作；绑定状态（含已解绑）仅作展示。

六、筛选字段说明（绑定明细页）

字段名称 字段说明 默认值
ID类型 下拉单选，共 5 项：邀请人角色ID、邀请人通行证ID、被邀请人角色ID、被邀请人通行证ID、被邀请人设备ID。无「全部ID」选项，必须先选定一个字段再输入。 邀请人角色ID
ID输入值 与 ID 类型联动，仅在所选字段内做精确匹配（全等），不做模糊包含、不跨字段匹配。例：选「被邀请人角色ID」输入 9900345，只命中该字段等于 9900345 的记录；输入 990 不会命中任何记录。为空时该条件不生效。 空
绑定状态 下拉单选，共 3 项：不限 / 有效 / 已解绑。「有效」= 当前生效的绑定关系，计入活动的有效绑定数；「已解绑」= 已被人工解除的记录，保留用于追溯，不计入有效绑定数。 不限
绑定时间 日期范围（开始日期 → 结束日期），取值为绑定关系建立的时间（即记录中的「绑定时间」字段，非解绑时间、非活动创建时间）。按日期粒度比较，含首尾两端（闭区间）；可只填开始或只填结束，单边生效。 空
（不限时间范围）

七、边界与异常

  • 无活动 / 活动无记录 → 表格展示空态。
  • 活动有进行中/已结束两种状态；进行中活动可点击"结束"，经二次确认后状态变为已结束，并模拟停止游戏请求。
  • 设备绑定唯一性限制：一个设备只能被一个角色ID绑定一次。发起绑定时校验该设备是否已存在绑定记录，若已被绑定则拒绝，并提示「绑定失败，当前设备已被绑定」。
  • 该校验在绑定发生时由服务端执行；本页为只读展示，已绑定的设备记录可通过「被邀请人设备ID」筛选查看。
  • 奖励规则配置不在本页，活动实体仅保存规则摘要文本用于展示。
