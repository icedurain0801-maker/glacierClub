0共同背景

本批次包含两个独立需求，二者都基于「角色验证码登录」这套验证流程——验证码不发短信/邮箱，而是发到游戏内角色的邮件，玩家凭角色邮件里的验证码完成身份核验。但两者是面向不同诉求、各自独立交付的需求，不能合并：

  • 需求一 · 角色登录：登录态只到角色维度。服务对象是渠道用户（红钻活动、企业微信活动）。
  • 需求二 · 账号登录：通过角色 ID 反查账号 ID，登录态到账号维度。服务对象是冰川自营各端 SDK 用户（如抖小、微小）。

共同点：① 验证渠道都是「游戏内角色邮件验证码」；② 都为网页活动做嫁衣，支持网页活动跳转登录、登录成功后回带登录态。共同的「验证码下发与核验机制」见下方各需求内描述（流程一致，差异在登录态产物）。

一需求一 · 角色验证码登录（角色维度）红钻 / 企微活动
1.1需求概述

定位：以游戏角色为身份锚点的轻量登录，登录态只到角色维度（角色 ID + 区服），不涉及账号体系。

服务对象：渠道用户。专为红钻活动、企业微信活动等渠道侧活动做嫁衣。这类活动只关心「是哪个角色」，不需要打通账号下的其他角色或账号级资产，因此用最短的角色维度登录即可。

价值：玩家在网页/企微侧无需记忆账密，输入角色 ID + 角色邮件验证码即可登录参与活动，登录门槛最低、转化最高。

1.2登录流程
  1. 玩家输入角色 ID，系统校验该角色是否真实存在。
  2. 角色校验成功 → 调用游戏侧发件接口，向该角色游戏内邮箱发送含验证码的邮件（6 位数字，有效期 5 分钟）。
  3. 玩家在游戏内读取验证码，回填登录页。
  4. 系统校验「角色 ID + 验证码」匹配且未过期 → 以角色身份登录，登录态 = 角色 ID + 区服 + 角色名。
为什么用游戏内邮件：能在游戏里收到并读取该角色的邮件，即证明操作人拥有此角色，无需再依赖手机号/邮箱等账号资产，验证与角色身份天然绑定。
1.3网页活动接入
  • 跳转登录：红钻/企微活动检测未登录时，携带回跳地址 + 活动标识跳转至本登录页。
  • 回带登录态：登录成功后将角色维度凭证（角色 ID / 区服 / 角色名）回带至活动页。
1.4异常与边界
  • 角色不存在：拦截在第一步，不发码，避免无效发件。
  • 验证码错误/过期：提示「验证码错误或已过期」，可重新获取；连续错误 5 次锁定防爆破。
  • 发码频控：同一角色 60s 仅可获取一次；按 IP/活动来源设日发码上限防刷。
  • 游戏侧发件失败：Toast 提示重试，不进入倒计时。
  • 回跳地址非法：redirect 不在白名单内拒绝跳转，防开放重定向。
二需求二 · 角色验证码登录（账号维度）抖小 / 微小等 SDK
2.1需求概述

定位：验证流程同样基于角色邮件验证码，但登录成功后由角色 ID 反查出账号 ID，最终登录态落到账号维度（通行证 ID）。

与需求一的本质区别：需求一停在角色；需求二多了一步「角色 ID → 账号 ID」映射，登录的是整个账号，可覆盖账号下多角色通用奖励、账号余额、跨角色资产等账号级权益的活动。

服务对象：冰川自营各端 SDK 用户（如抖小、微小等小程序端）。这类端有自己的账号体系，活动需要账号级身份与权益，因此登录态要落到账号维度。

定位边界（重要）：本登录只是补充登录入口，仅在活动场景下使用，不替代各端的原生登录。抖小、微小等端在 App 内的常规登录仍走各自的原生登录（抖音/微信授权等）；只有当端内活动需要账号身份、而当前缺少可用登录态时，才走本「角色验证码登录」作为补充通道完成账号维度登录。
2.2登录流程
  1. 玩家输入角色 ID，系统校验该角色是否真实存在。
  2. 角色校验成功 → 向该角色游戏内邮箱发送验证码邮件（6 位数字，有效期 5 分钟）。
  3. 玩家读取验证码并回填。
  4. 校验「角色 ID + 验证码」通过 → 由角色 ID 反查绑定的账号 ID。
  5. 映射成功 → 以账号身份登录，登录态 = 账号 ID（通行证 ID）+ 当前验证角色 ID。
映射环节关键约束：角色 ID → 账号 ID 必须唯一且实时。需明确：① 一个角色是否只属于一个账号（预期是）；② 角色被转移/找回后映射如何同步更新；③ 映射查询失败（游戏侧接口超时）时必须拦截登录而非放行，杜绝登错账号。
2.3网页活动接入
  • 跳转登录：活动检测未登录时携带回跳地址 + 活动标识跳转至本登录页。
  • 回带登录态：登录成功后将账号维度凭证（账号 ID + 验证角色 ID）回带至活动页。
待你确认：账号维度登录后，若该账号下有多个角色，活动上下文是固定为验证用的那个角色，还是允许在账号的多角色间切换？此点影响活动侧角色选择交互，需明确。
2.4异常与边界
  • 角色不存在：拦截在第一步，不发码。
  • 验证码错误/过期、发码频控、发件失败：同需求一。
  • 账号映射失败（核心差异）：角色存在但查不到绑定账号 → 明确提示「该角色未绑定账号，无法以账号方式登录」，不得静默放行或登错账号。
  • 回跳地址非法：redirect 白名单校验，防开放重定向。
3登录页字段定义（两需求共用）
字段控件必填校验 / 说明
角色 ID文本输入是失焦即校验角色是否存在；不存在时下方红字提示「未找到该角色ID」，并禁用「获取验证码」
角色信息回显文本（只读）—角色校验通过后展示「角色ID - 角色名 - 区服」，供玩家确认身份
验证码文本输入是6 位数字；有效期 5 分钟；最多输入 6 位
获取验证码按钮—角色校验通过后才可点；点击后 60s 倒计时防刷；结束后变「重新获取」
验证并登录按钮—角色 + 验证码均通过后高亮可点；按所属需求产出角色维度 / 账号维度登录态
登录页 UI 与字段两需求一致，差异仅在验证通过后的后端处理（需求一止于角色、需求二多一步账号映射）与回带给活动的登录态维度。
