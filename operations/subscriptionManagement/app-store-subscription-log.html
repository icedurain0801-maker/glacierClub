应用商店订阅日志查询 — 需求说明
1需求概述

背景与目标：目前各渠道（GooglePlay / AppStore / 华为 / 小米等）的订阅数据分散于各平台，运营及客服人员无统一入口查询和处理异常订阅，导致用户反馈处理效率低、取消订阅操作依赖研发介入。本页面旨在提供统一的订阅日志查询与管理能力，支持多维度筛选、订阅状态全链路查看、单条及批量取消订阅操作，降低研发介入成本，提升运营处理时效。

菜单地址：在运营中心新增订阅管理子菜单，然后在子菜单里新增子页面应用商店订阅日志查询。

2页面交互流程
核心操作流：取消订阅
  • 单条流程：进入页面 → 输入筛选条件 → 点击「查询」→ 定位目标行 → 点击「取消订阅」→ 弹窗确认（填写订阅结果 + 备注）→ 确认提交 → 系统调用渠道接口 → 成功：行状态变为「已取消」并写入操作备注；失败：弹窗保留、Toast 报错。
  • 批量流程：勾选多行（已取消行不可选）→ 「批量取消订阅」按钮激活 → 弹窗展示已选数量 → 填写统一备注 → 确认提交 → 系统逐条调用渠道接口 → Toast 展示「成功 X 条，失败 Y 条」（部分失败时保留失败项可重试）。
导出流程
  • 点击「导出」→ 按当前筛选条件下发导出任务 → 数量 ≤ 10 万条时直接下载 Excel；超量时 Toast 提示「数据量过大，请缩小筛选范围后重试」，不触发下载。

6功能逻辑与联动规则
筛选联动
  • 「平台」切换后，列表数据立即重置，已勾选行清空，重新执行查询（当前筛选条件保留）。
  • 「用户标识类型」切换后，右侧输入框清空已填内容，placeholder 更新为对应类型提示。
  • 日期范围组件：点选开始日期后，结束日期不可早于开始日期；均为空时不作为筛选条件。
复选框与批量按钮联动
  • 页头全选框：勾选 = 全选当前页中状态非「已取消」的行；若全部可选行已勾选，则再次点击为全部取消。
  • 已选数量实时更新于按钮旁「已选 X 项」，X = 0 时批量按钮置灰不可点。
  • 翻页或重新查询后，已勾选行清空（避免跨页误操作）。
取消订阅提交逻辑
  • 单条：确认提交后，按钮进入 loading 防抖状态，接口返回前不可重复点击。
  • 成功：弹窗关闭，列表局部刷新该行状态，Toast「取消订阅成功：{平台订单ID}」。
  • 失败：弹窗保留已填内容，Toast 报错提示，允许用户重新提交。
  • 批量：后端逐条处理并返回明细结果；全成功时 Toast「批量取消订阅成功，共 X 条」；部分失败时 Toast「成功 X 条，失败 Y 条」，失败行保持可勾选状态以便重试。
7异常与边界情况
数据异常
  • 列表为空：展示空状态图+文案「暂无数据，请调整筛选条件后重试」，不展示表格骨架。
  • 字段缺失：后端返回 null 或空字符串的字段，前端统一展示 "—"，不显示 "null" / "undefined"。
  • 详情 JSON 异常：若渠道原始通知格式错误，原样展示原始字符串，不强制解析。
性能与容量
  • 查询无条件保护：所有筛选项均为空时，禁止查询（按钮置灰或提示「请至少填写一个筛选条件」），避免全表扫描。
  • 日期跨度限制：单次查询日期跨度建议 ≤ 180 天，超出时前端拦截提示。
  • 导出数量上限：10 万条；超出时提示缩小筛选范围，不触发后端任务。
  • 批量操作上限：单次批量取消订阅建议 ≤ 200 条，超出时提示「单次批量操作上限 200 条，请分批操作」。
权限边界
  • 查询权限：所有已登录运营人员默认拥有。
  • 取消订阅权限：需「订阅管理-操作」权限；无权限时「取消订阅」链接和「批量取消订阅」按钮不展示（隐藏，非置灰），页面不出现操作入口。
  • 导出权限：需「订阅管理-导出」权限；无权限时「导出」按钮隐藏。
操作异常
  • 并发冲突：同一订阅被两人同时操作，后提交者接口返回状态冲突时，提示「该订阅已被处理，请刷新后确认」，不静默失败。
  • 网络断开：提交失败统一展示 Toast 错误提示，弹窗保留内容可重试；不自动重试（避免重复取消）。
  • 渠道接口异常：渠道侧返回错误码时，展示具体错误信息（如「渠道侧订单不存在」），便于人工判断是否重试。
  • 会话过期：操作提交时若会话已过期，跳转登录页，操作不执行。
⚠️ 取消订阅为不可逆操作，直接调用渠道侧接口终止续订权益。弹窗中需明确展示被操作订单的关键信息（平台订单ID、产品ID），并要求操作者主动选择「订阅结果」，避免误触。
