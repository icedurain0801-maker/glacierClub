# 社区接入三步流程调整设计

## 目标

将社区接入引导调整为更符合接入认知顺序的三步流程：

1. 功能介绍
2. 功能选择
3. 社区名称填写和提交工作流

## 交互设计

第一步为静态介绍页，说明社区接入可提供的功能范围与后续步骤，不显示表单或勾选项；点击“开始选择功能”进入第二步。

第二步保留现有功能模块复选表单。用户至少选择一个功能后，点击确认按钮进入第三步；可返回第一步重新阅读介绍。

第三步承载现有社区名称、游戏 ID、游戏版本、接入形态、发行地区和游戏类型字段。点击“提交接入工作流”时执行现有必填校验并保存接入信息；提交成功后展示接入摘要，并保留链接生成和错误排查入口。

## 实现边界

- 继续使用 `communityTools/index.html` 现有原生 HTML、CSS 和 JavaScript 结构。
- 复用现有步骤条、`obShowStep`、功能选择状态和摘要渲染逻辑。
- 将工作流提交动作从第一步移动到第三步，不新增后端接口。
- 同步更新步骤条标签、面板说明、首页社区接入卡片的顺序文案。

## 数据流

功能介绍 -> 功能选择并保存 `obData.feats` -> 填写接入信息并保存 `obData` -> 生成接入摘要 -> 进入运营工具。

## 校验与边界

- 功能选择为空时，继续提示至少选择一个功能，不进入第三步。
- 第三步社区名称、游戏 ID 或游戏版本为空时，继续阻止提交。
- 返回前一步不清除已选择功能或已填写的接入字段。
- 第三步提交后仍可通过已有摘要查看接入信息，不改变链接工具行为。

## 验证

- 静态检查页面中三步标签、面板顺序和按钮调用关系。
- 使用浏览器验证默认进入第一步、步进切换、返回、功能勾选和第三步提交校验。
